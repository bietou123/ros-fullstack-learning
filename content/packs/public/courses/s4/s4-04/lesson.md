# S4-04 · 串口、RS485 与 Modbus RTU

> 验证状态：✅ CRC16 算法与报文构造已在本地用脚本验算（`01 03 00 00 00 0A` → CRC `0xC5CD`，低位在前）；串口/RS485 硬件部分**未实测**。

## 1. 现场类比

不是所有设备都上 CAN。传感器、电表、部分 PLC 走 RS485 + Modbus RTU。现场典型问题：

- A/B 线接反 → 完全收不到；
- 终端电阻/偏置缺失 → 白天好、晚上坏；
- 多主站同时说话 → 数据错乱。

## 2. 核心概念

### 2.1 物理层

| 项目 | 内容 |
|---|---|
| RS485 | 差分半双工，两线 A/B |
| 连接 | 总线型，手拉手，不要星型 |
| 终端 | 长线两端各 120Ω |
| 偏置 | 空闲时保证 A>B，部分设备内置 |
| 距离/速率 | 1200m@100k 以下；速率越高距离越短 |

USB 转 485 适配器很常见，但**不同芯片的时序能力差异很大**，高频轮询会丢帧。

### 2.2 Modbus RTU 帧

```
从站地址(1B) | 功能码(1B) | 数据(NB) | CRC16(2B, 低字节在前)
```

| 功能码 | 作用 |
|---|---|
| 0x01 | 读线圈 |
| 0x03 | 读保持寄存器 |
| 0x04 | 读输入寄存器 |
| 0x06 | 写单个寄存器 |
| 0x10 | 写多个寄存器 |

**帧间静默 ≥3.5 个字符时间**是 RTU 的帧边界判据，不是随便加延时。

### 2.3 CRC16 验算（可复制）

```python
def crc16_modbus(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

frame = bytes([0x01, 0x03, 0x00, 0x00, 0x00, 0x0A])
c = crc16_modbus(frame)
print(hex(c))                 # 0xcdc5
print(frame.hex(), f"{(c & 0xff):02x}{(c >> 8):02x}")
```

预期：`0xcdc5`，最终报文 `01030000000ac5cd`。

**CRC 是低字节在前**，写成高字节在前是最常见的低级错误。

### 2.4 寄存器与地址

- 协议文档常写 40001 起，实际报文地址从 0 开始（差 1）；
- 一个寄存器 16 位，32 位量占两个寄存器，**字序（高低字）** 需确认；
- 有符号数要用补码解释，别当成无符号。

## 5. 自动检查

无需硬件，直接验证 CRC 实现：

```bash
python3 -c "d=bytes([1,3,0,0,0,10]); c=0xFFFF
for b in d:
    c^=b
    for _ in range(8): c=(c>>1)^0xA001 if c&1 else c>>1
print(hex(c))"
```

预期输出 `0xcdc5`。

## 6. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 完全无响应 | A/B 接反 | 对调两根线 |
| 偶发 CRC 错 | 线太长/无终端电阻/干扰 | 加 120Ω、屏蔽接地 |
| 只有部分从站响应 | 地址重复/超时太短 | 查地址、加超时 |
| 数值差 1 个寄存器 | 40001 与 0 的偏移 | 报文地址减 40001 |
| 32 位数值乱 | 字序不同 | 交换高低字验证 |
