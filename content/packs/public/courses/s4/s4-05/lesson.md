## 1. 现场类比

CAN 一帧 8 个字节，PLC 往往不按整字节用，而是把多个信号塞进同一个字节/字里：

```
bit0-1  : 工作模式
bit2    : 使能
bit3-4  : 故障等级
bit5-15 : 转速原始值（需要乘缩放系数）
```

**位域读错一位，可能把「使能」读成「急停」。** 这类错误不会报错，只会让车做出错误动作——所以必须逐位核对。

## 2. 核心概念

### 2.1 三个必须问清的问题

| 问题 | 影响 |
|---|---|
| 字节序/位序 | 大端还是小端，bit0 在最高位还是最低位 |
| 缩放因子与偏移 | 物理量 = raw × scale + offset |
| 有无符号 | 负角度、负电流必须按补码解释 |

**这三项不确认，任何数值都不能信。**

### 2.2 示例解码（虚构协议）

假设 2 字节（16 位）小端，定义如下：

| 位段 | 含义 |
|---|---|
| bit0-1 | 模式：0=空闲 1=手动 2=自动 3=故障 |
| bit2 | 使能 |
| bit3-4 | 故障等级 0–3 |
| bit5-15 | 转速原始值，scale=0.5，单位 rpm |

```python
def decode_status(raw_bytes: bytes) -> dict:
    v = int.from_bytes(raw_bytes, "little")
    return {
        "mode":      v & 0b11,
        "enabled":   bool((v >> 2) & 1),
        "fault_lvl": (v >> 3) & 0b11,
        "rpm":       (v >> 5) * 0.5,
    }

print(decode_status(bytes([0x8A, 0x20])))
```

预期输出：`{'mode': 2, 'enabled': False, 'fault_lvl': 1, 'rpm': 130.0}`。

### 2.3 编码是解码的逆运算

```python
def encode_status(mode, enabled, fault_lvl, rpm):
    v = (mode & 0b11) | ((1 if enabled else 0) << 2)
    v |= (fault_lvl & 0b11) << 3
    v |= (int(round(rpm / 0.5)) & 0x7FF) << 5
    return v.to_bytes(2, "little")
```

**必须做往返测试**：`decode(encode(x)) == x`。只写解码不写编码，等于只检查了一半。

### 2.4 位域与掩码的现场对照法

```
1. 用协议文档列出每一位；
2. 造一帧「只有一个位为 1」的数据；
3. 看设备反应是否与预期一致；
4. 逐位过一遍，记录结果。
```

这是最笨但最可靠的方法，比盯着十六进制猜快得多。

## 4. 动手实验

**目标（40 分钟）**：为你自己的协议写一个双向编解码器。

1. 按 2.2 的示例写出 `decode_status` 与 `encode_status`；
2. 对 0…65535 全量做往返测试，确认无偏差；
3. 把 `raw` 改成大端再跑一遍，记录哪些字段变了；
4. 用「单位位=1」的方法逐位验证；

**通过判据**：65536 个值往返测试全部通过，且能解释大端/小端切换后哪些字段出错。

## 6. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 使能/模式乱跳 | 位序理解反了 | 用单位位法逐位验证 |
| 数值差固定倍数 | 缩放因子错 | 用满量程值反推 |
| 负值变大正数 | 未按有符号解释 | 用补码转换 |
| 32 位值只有一半对 | 字序错 | 交换高低 16 位 |
| 编解码往返不一致 | 掩码越界/取整方式 | 加往返测试 |
