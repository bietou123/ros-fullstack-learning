# S5-07 · 坐标系、欧拉序与符号核对

> 验证状态：✅ 本课旋转顺序、四元数与坐标系转换命令已在本机 Linux 实测；⚠ 未接实机验证具体驱动的坐标约定，实际约定以设备手册为准。

## 1. 现场类比

同一组姿态数据，两个人算出两个方向：一个人按「先绕 x 再绕 y」，另一个按「先绕 y 再绕 x」。**数据一模一样，结果完全不同，而且都不报错。**

更常见的是坐标系混用：算法用「前-左-上」，相机用「右-下-前」，直接拿过来用，画面里的目标永远偏 90°。

**方向问题不报错，只出错。** 所以必须有核对表，而不是靠记忆。

## 2. 核心概念

### 2.1 一个坐标系必须说清五件事

| 项目 | 说明 | 例子 |
|---|---|---|
| 原点 | 在哪里 | 铰点中心、IMU 芯片中心 |
| 轴向 | 三个轴正方向 | x 向前、y 向左、z 向上 |
| 手性 | 右手系 / 左手系 | 统一用右手系 |
| 单位 | 米 / 毫米、弧度 / 度 | 内部统一 SI |
| 名称 | frame_id | `base_link`、`imu_link` |

**五件事少一件，就埋一个坑。**

### 2.2 三种旋转表示

| 表示 | 参数 | 优点 | 缺点 |
|---|---|---|---|
| 旋转矩阵 R | 9（含 6 个约束） | 无歧义、可直接乘 | 冗余，数值误差累积 |
| 四元数 q | 4（需归一化） | 紧凑、可插值、无万向锁 | 符号双覆盖，q 与 −q 等价 |
| 欧拉角 | 3 | 人易读 | **顺序/内外旋不写清就有歧义**，有万向锁 |

工程建议：**存储与计算用四元数或旋转矩阵，只在显示和录入时转欧拉角，并且必须写清顺序。**

### 2.3 欧拉序为什么必须写清

同样的 (30°, 45°, 60°)：

- `Rz(60)·Ry(45)·Rx(30)`（常见 roll-pitch-yaw，绕固定轴 x→y→z）
- `Rx(30)·Ry(45)·Rz(60)`（顺序反过来）

结果是两个不同姿态。常见的「12 种欧拉角约定」正是由「三个轴怎么排 + 内旋还是外旋」组合出来的。

**写欧拉角时至少写三件事：顺序（如 xyz）、内旋/外旋、单位。**

### 2.4 四元数的两个坑

1. **顺序**：`(w,x,y,z)` 还是 `(x,y,z,w)`？ROS/很多库用 `(x,y,z,w)`，数学教材常用 `(w,x,y,z)`；
2. **双覆盖**：`q` 与 `-q` 表示同一个旋转，插值或比较时要选同侧（点积为负则取反）。

### 2.5 body 系与相机光学系

| 坐标系 | x | y | z |
|---|---|---|---|
| 机器人 body（FLU） | 前 | 左 | 上 |
| 相机光学系 | 右 | 下 | 前 |

两者差一个固定旋转，**不能混用**。转换关系：

```
x_cam = -y_body
y_cam = -z_body
z_cam =  x_body
```

### 2.6 符号核对表

每个进入算法的量都填一行，填不出来的就是风险点：

| 量 | 定义 | 正方向 | 单位 | 所在坐标系 | 来源 |
|---|---|---|---|---|---|
| 关节角 q1 | 动臂相对水平 | 抬臂为正 | rad | base | 角度传感器 |
| 角速度 ω | 绕 z 轴 | 逆时针为正 | rad/s | imu_link | IMU |
| 加速度 a | 比力 | 指向重力反方向 | m/s² | imu_link | IMU |

## 3. 可复制命令 / 代码

```bash
# 同样 90° 的两次旋转，顺序不同结果不同
python3 -c "rx=lambda p:(p[0],-p[2],p[1]); ry=lambda p:(p[2],p[1],-p[0]); print('Rx_then_Ry=%s'%(ry(rx((1,0,0))),)); print('Ry_then_Rx=%s'%(rx(ry((1,0,0))),))"

# 四元数：绕 z 转 90°，检查模长与 q / -q 等价
python3 -c "import math; w=math.cos(math.radians(45)); s=math.sin(math.radians(45)); print('norm=%.6f'%(math.sqrt(w*w+s*s))); print('q=(%.4f,0,0,%.4f) -q=(%.4f,0,0,%.4f)'%(w,s,-w,-s))"

# body(前-左-上) 的前向点，映射到相机光学系(右-下-前)
python3 -c "p_body=(1.0,0.0,0.0); p_cam=(-p_body[1],-p_body[2],p_body[0]); print('body_forward=%s -> cam_optical=%s'%(p_body,p_cam))"
```

预期：`Rx_then_Ry=(0,0,-1)` 而 `Ry_then_Rx=(0,1,0)`；四元数模长 `1.000000`；body 前向映射到光学系 `(0,0,1)`（相机 z 轴朝前）。

## 4. 动手实验

**目标（40 分钟）**：为你手上的一个传感器/驱动填完符号核对表，并用代码验证旋转约定。

1. 找一个你实际使用的接口（IMU、关节、相机均可）；
2. 查出它输出的每个量的坐标系、正方向、单位；
3. 填满符号核对表的每一列，**填不出的标「待确认」**；
4. 用本课代码验证：两次旋转顺序是否真的不可交换；
5. 写一段「坐标系转换」说明：从传感器坐标系到 body 坐标系，需要哪些旋转；
6. 找一个反例：如果符号错了，现象会是什么？怎么用最小实验验证？

**通过判据**：核对表无空项（或明确标注待确认），并能用一段代码复现「顺序不同、结果不同」。

## 5. 自动检查

```bash
python3 -c "rx=lambda p:(p[0],-p[2],p[1]); ry=lambda p:(p[2],p[1],-p[0]); import math; w=math.cos(math.radians(45)); s=math.sin(math.radians(45)); p=(1.0,0.0,0.0); assert ry(rx(p))!=(0,1,0) and abs(math.hypot(w,s)-1)<1e-9; print('FRAME_OK')"
```

预期输出 `FRAME_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 姿态「转对了方向但角度不对」 | 欧拉序约定不同 | 明确顺序与内外旋 |
| 目标在图像中偏移 90° | body 与相机光学系混用 | 用固定旋转转换 |
| 四元数插值出现抖动 | q 与 −q 未对齐 | 点积为负时取反 |
| 姿态矩阵越来越不准 | 反复乘旋转矩阵未正交化 | 定期归一化/用四元数 |
| 单轴测试正常、组合动作错 | 左右手系混用 | 统一右手系 |
| 角度符号相反 | 正方向定义不一致 | 回到符号核对表 |
| 不同模块对同一 frame 理解不同 | 缺 frame 约定文档 | 写清五要素并评审 |
