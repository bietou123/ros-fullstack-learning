# S7-04 · 代价地图

> 验证状态：✅ 本课膨胀代价计算命令已在本机 Linux 实测；⚠ 未运行真实 Nav2 代价地图，参数与阈值均为**教学示例**。

## 1. 现场类比

路上只有一根细柱子，规划器却绕了一大圈。不是它笨，是**柱子周围的「代价」被膨胀得太宽**，整片区域都被当成不能走。

代价地图是导航的「地形图」：哪里能走、哪里难走、哪里绝对不能走，都写在一张 0–255 的格子里。

## 2. 核心概念

### 2.1 代价的含义

| 值 | 含义 |
|---|---|
| 0 | 自由空间 |
| 1–252 | 代价值，越大越靠近障碍 |
| 253 | 内切障碍（inscribed），机器人中心在此必碰撞 |
| 254 | 致命障碍（lethal），实际障碍 |
| 255 | 未知区域（unknown） |

路径规划倾向于「代价最小」，所以膨胀层决定了机器人「离墙多远走」。

### 2.2 分层结构

| 层 | 来源 | 作用 |
|---|---|---|
| static layer | 静态地图 | 墙、固定结构 |
| obstacle layer | 激光/点云 | 实时障碍 |
| voxel layer | 3D 点云 | 三维障碍投影 |
| inflation layer | 上述障碍 | 按距离生成代价 |
| 自定义层 | 业务规则 | 禁行区、减速区 |

**顺序很重要**：先有障碍，再做膨胀；后加的层会覆盖前面的值。

### 2.3 膨胀与 footprint

- `robot_radius`：圆形近似，简单但保守；
- `footprint`：多边形，精确但开销大；
- `inflation_radius`：从障碍向外生成代价的最大距离；
- `cost_scaling_factor`：代价随距离衰减的快慢。

**膨胀半径至少要覆盖「机器人中心到轮廓最远点」**，否则会擦墙。

### 2.4 更新频率的取舍

| 参数 | 太小 | 太大 |
|---|---|---|
| 更新频率 | 障碍反应慢 | CPU 占用高 |
| 障碍衰减时间 | 幽灵障碍残留 | 真实障碍被过早清除 |
| 膨胀半径 | 容易擦墙 | 通道变窄、规划失败 |

## 3. 可复制命令 / 代码

```bash
# 膨胀代价：内切 0.2 m 内为 254，0.5 m 外为 0，中间线性衰减
python3 -c "ri=0.2; ro=0.5; c=lambda d:254 if d<=ri else (0 if d>=ro else int(252*(ro-d)/(ro-ri))); print([(x,c(x)) for x in (0.1,0.2,0.35,0.5)])"
```

预期：`[(0.1,254),(0.2,254),(0.35,126),(0.5,0)]`。距离障碍 0.35 m 时仍有约一半代价——这就是「绕着走」的来源。

## 4. 动手实验

**目标（35 分钟）**：为一台设备定出代价地图参数，并解释每个参数的理由。

1. 测量机器人轮廓，决定用圆形半径还是多边形 footprint；
2. 找到轮廓最远点距离，设 `inflation_radius` 不低于它；
3. 设定更新频率与障碍衰减时间，说明依据；
4. 用本课公式画出「距离 → 代价」曲线；
5. 在一张静态地图上标注：通道宽度、安全余量、需要减速的区域；
6. 写结论：当前参数下，最窄通道能否通过？哪里最容易误判？

**通过判据**：每个参数都有数值和理由；最窄通道宽度 > 机器人宽度 + 2×安全余量。

## 5. 自动检查

```bash
python3 -c "ri=0.2; ro=0.5; c=lambda d:254 if d<=ri else (0 if d>=ro else int(252*(ro-d)/(ro-ri))); assert c(0.1)==254 and c(0.35)==126 and c(0.5)==0; print('COSTMAP_OK')"
```

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 无缘无故绕远 | 膨胀半径太大/代价尺度太陡 | 调小半径或降低缩放因子 |
| 擦墙、贴障碍太近 | 膨胀半径小于轮廓最远点 | 重新测 footprint |
| 障碍物消失很慢 | 未做射线清除/衰减时间太长 | 检查传感器视野与 clearing |
| 动态障碍反复触发恢复 | 障碍层更新频率/过滤不足 | 调更新频率，加滤波 |
| 规划器报无可行路径 | 通道被膨胀封死 | 看通道有效宽度 |
| CPU 占用高 | 地图分辨率过高、更新过频 | 降分辨率/频率 |
| 全局与局部地图不一致 | 更新频率和来源不同 | 明确两层职责，分别调参 |
