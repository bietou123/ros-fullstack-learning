# S7-02 · 定位与地图维护

> 验证状态：✅ 本课粒子权重与置信度判据命令已在本机 Linux 实测；✅ 2026-11-06 在 `ros:humble` + `nav2_amcl` 容器内用合成激光/里程计与 8×6 m 房间地图完成 AMCL 全程跟踪实测（24 s、360 线、0.5% 里程尺度误差；位置误差 0.004–0.024 m，航向误差 ≤0.8°，协方差 3e-3–1e-2 m²）；⚠ 真实激光雷达与实车定位仍未实测。

## 1. 现场类比

地图上显示机器在门口，实际已经在柱子后面。定位一旦悄悄跑偏，路径规划再漂亮也是错的。

更常见的是：厂房改了一面墙、堆了一批料，地图还是旧的——**定位不是一次性的，地图也不是。**

## 2. 核心概念

### 2.1 定位分两种

| 模式 | 初始位姿 | 方法 | 使用场景 |
|---|---|---|---|
| 全局定位 global localization | 未知 | 粒子滤波撒满地图、多假设 | 开机、被搬动、重定位 |
| 局部跟踪 local tracking | 已知（或上次位置） | 扫描匹配、局部粒子 | 正常运行 |

**「 kidnapped robot 」问题**：机器被人搬走了，局部跟踪会固守错误位置。需要能检测「匹配突然变差」并触发全局重定位。

### 2.2 粒子滤波在做什么

1. 撒一批粒子表示「我可能在哪」；
2. 每个粒子按观测计算权重（谁解释得通，谁权重高）；
3. 重采样：高权重的粒子多复制，低权重的淘汰；
4. 粒子越集中，置信度越高。

判断收敛看：权重是否集中、粒子分布范围（协方差）、匹配得分是否稳定。

### 2.3 有效粒子数 ESS

```
ESS = 1 / Σ w_i²
```

权重越集中，ESS 越小。ESS 接近粒子总数 → 还没收敛或观测无区分度；ESS 掉到很小时 → 可能只剩一个假设。

### 2.4 地图维护

| 变化 | 影响 | 处理 |
|---|---|---|
| 新增固定结构 | 定位出现偏差/匹配率下降 | 重扫更新地图 |
| 临时堆放物料 | 局部匹配变差 | 标记为动态/临时层，不改静态图 |
| 区域改造 | 地图整体失效 | 重测、升版本 |
| 地图版本不一致 | 多台设备定位不一致 | 统一版本号，启动时校验 |

**地图要有版本号、日期、负责人在文件里**，没有版本的地图等于没有地图。

## 3. 可复制命令 / 代码

```bash
# 粒子权重 [0.1,0.2,0.4,0.2,0.1] 的有效粒子数
python3 -c "w=[0.1,0.2,0.4,0.2,0.1]; s=sum(w); wn=[x/s for x in w]; print('ess=%.2f'%(1/sum(x*x for x in wn)))"

# 定位协方差的 xy 方差 0.09 → 标准差 0.30 m，是否可作为可信位置
python3 -c "import math; cov_xy=0.09; sig=math.sqrt(cov_xy); print('sigma_m=%.2f trusted=%s'%(sig,sig<0.5))"
```

预期：`ess=3.85`（5 个粒子中约 3.85 个「有效」，说明权重比较集中但未极端）；`sigma_m=0.30 trusted=True`。

## 4. 动手实验

**目标（35 分钟）**：记录一次定位收敛过程，并定义「可以开始作业」的判据。

1. 启动定位（仿真或实机），先给错误初始位姿；
2. 每隔 1 s 记录：粒子分布范围、匹配得分、定位协方差；
3. 观察多久收敛，收敛前是否出现多峰；
4. 人为遮挡传感器 / 搬动设备，观察定位如何变化；
5. 定义作业启动判据（如：连续 5 s 协方差 < 阈值且匹配得分稳定）；
6. 写结论：当前参数下收敛时间多少？哪些情况会导致不收敛？

**通过判据**：有收敛时间线、有明确启动判据，且能识别至少一种「定位失效」的场景。

## 5. 自动检查

```bash
python3 -c "import math; w=[0.1,0.2,0.4,0.2,0.1]; s=sum(w); wn=[x/s for x in w]; ess=1/sum(x*x for x in wn); sig=math.sqrt(0.09); assert abs(ess-3.846)<0.01 and sig<0.5; print('LOCALIZATION_OK')"
```

预期输出 `LOCALIZATION_OK`。

**可复现的 AMCL 跟踪实测**：在 `ros:humble` 基础上装 `ros-humble-nav2-map-server`、`ros-humble-nav2-amcl`、`ros-humble-nav2-lifecycle-manager`，用 168×128 @0.05 m 的 8×6 m 房间栅格图（原点 `[-4.2, -3.2, 0.0]`，四墙精确落在 x=±4.0、y=±3.0），`map_server` 与 `amcl` 分别 `ros2 lifecycle set ... configure/activate`。AMCL 关键参数：`scan_topic:=/scan`、`global_frame_id:=map`、`odom_frame_id:=odom`、`base_frame_id:=base_link`、`laser_model_type:=likelihood_field`、`set_initial_pose:=true`、`initial_pose.*` 从已知起点给；跟踪记录时把 `update_min_d`/`update_min_a` 调到 `0.05`（默认 0.25 m / 0.2 rad 会让 `/amcl_pose` 明显滞后）。仿真节点发 360 线 `/scan`、`odom→base_link`（含 0.5% 尺度与航向漂移）和 `base_link→laser` 静态外参，24 s 内机器人绕 2 m 半径一圈；按 `msg.header.stamp` 把 `/amcl_pose` 与解析真值对齐后，实测位置误差 0.004–0.024 m、航向误差 ≤0.8°、协方差 3e-3–1e-2 m²。

三个实测踩坑（都会让定位「看起来能用但一直偏」）：
- 地图几何必须与仿真/现场一致：直接拿带裁切误差的 SLAM 输出当基准，墙面纵向偏移约 0.1 m，会把位置误差稳定抬高到 0.16–0.19 m；换成墙面对齐的图后误差立即回到厘米级。
- 激光外参要与数据来源一致：TF 声明 `base_link→laser` 有 0.1 m 前移、但扫描是从 `base_link` 原点生成的，AMCL 按外参补偿后会产生随航向变化的固定偏差（实测约 0.07–0.09 m）。
- 真值对齐要用消息时间戳：拿「打印时刻」的解析真值去比 `amcl_pose`，机器人一直在动，会把正常的 1–2 帧延迟误判成定位误差。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 定位一直跳 | 地图重影、观测特征少 | 先修地图，增加特征 |
| 运行中慢慢跑偏 | 里程计漂移、外参误差 | 检查里程计标定与外参 |
| 被搬动后不恢复 | 只做局部跟踪 | 检测匹配失败并触发全局重定位 |
| 换地图后定位错 | 地图版本不一致 | 启动校验版本号 |
| 人多时定位不稳 | 动态障碍污染观测 | 使用动态层/滤波，提高匹配鲁棒性 |
| 初始位姿给错但「看起来正常」 | 未检查协方差与匹配分 | 加启动判据，不只看画面 |
| 多台设备定位结果不同 | 地图/外参/时间不同步 | 统一地图版本与标定参数 |
