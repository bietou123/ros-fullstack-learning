# S0-01 · 机器人全栈地图：从座舱指令到电磁阀

> 验证状态：概念课，无命令执行；文中术语与分层模型来自通用工程实践，不涉及任何客户数据。

## 1. 现场类比

坐在座舱里推一下手柄，挖掘机的动臂抬起来。你看到的是「一个动作」，背后其实穿过了至少五层系统：

1. 座舱控制器把你推杆的角度变成数字量；
2. 远控链路把数字量打包发到车上；
3. 车端计算机把指令翻译成比例阀电流；
4. 液压系统响应电流，油缸动作；
5. 传感器把实际角度反馈回来，闭环比对。

任何一层断了，动作都不会发生。**全栈学习的目标不是把五层都学成专家，而是任何一层异常时，你能判断问题在哪一层、用哪条命令把它证伪。** 这就是「交付实施工程师」和「只会点按钮的操作员」的区别。

## 2. 核心概念

### 2.1 五层模型（从下往上）

| 层 | 典型对象 | 你现场会碰到的单词 | 出问题时的典型症状 |
|---|---|---|---|
| L1 执行与电气 | 电磁阀、比例阀、继电器、线束 | 24V、PWM、共地、保险 | 完全不动 / 单方向不动 / 抖动 |
| L2 控制器与总线 | PLC、VCU、CAN 收发器 | CAN_H/CAN_L、500k、终端电阻 | 偶发丢帧 / 总线错误计数上涨 |
| L3 计算与中间件 | Linux 工控机、ROS1/ROS2 | node、topic、launch、QoS | 话题有数据但延迟大 / 无订阅者 |
| L4 算法与控制 | 坐标变换、限幅、状态机 | TF、PID、限位、使能 | 方向反、幅度不对、越限 |
| L5 业务与交互 | 远控台、监控界面、日志 | 会话、心跳、配置表 | 连不上 / 界面不动但车在动 |

### 2.2 一次指令的完整旅程（示例）

以「动臂上升」为例，数据流可以抽象为：

```
推杆 ADC → 座舱 MCU → 无线/有线链路 → 车端桥接 → ROS topic
        → 控制节点（限幅、斜率）→ CAN 报文 → PLC/驱动器
        → 比例阀电流 → 液压动作 → 角度传感器 → 反馈 topic
```

注意两个工程事实：

- **指令是「值 + 时间戳 + 序号」的组合**，不只是值。丢了时间戳，接收端无法判断该用新值还是旧值。
- **反馈不是可选项**。没有反馈的系统只能开环，现场表现为「推一点走过头、松手还在动」。

### 2.3 三张必须会画的图

1. **数据流图**：谁产生、谁转发、谁消费；
2. **地址/映射表**：每个信号对应哪个 CAN ID、哪几个字节、什么系数；
3. **故障树**：从「不动」反推到电源、总线、节点、驱动、机械。

本课产出物就是第一张图。后两张在 S4、S5 逐步补齐。

## 3. 可复制命令 / 代码

本课没有强制命令。建议在任意 Linux 机器上跑下面三条，建立「先看状态、再看数据」的习惯：

```bash
uname -a                  # 我在什么内核、什么架构
ip -br addr               # 我有哪些网卡和地址
ss -tlnp                  # 哪些端口在监听、被谁监听
```

判读要点：

- `uname -m` 为 `aarch64` 时，说明是 ARM64 设备（很多车载/嵌入式工控机）；
- 没有 `eth0` 但有 `enp*`/`end*` 是正常的可预测网卡命名；
- `ss` 输出里 `LISTEN` 后面的地址决定「谁能连进来」：`0.0.0.0` 表示所有网卡，`127.0.0.1` 表示只本机。

## 4. 动手实验

**目标（15 分钟）**：画出你手上项目的数据流图，至少 6 个节点、标明每段的物理介质。

步骤：

1. 在纸上写最左边「人」、最右边「机械动作」；
2. 中间按「采集 → 传输 → 计算 → 驱动 → 反馈」补节点；
3. 每两个节点之间标注介质（CAN / 以太网 / 无线 / 模拟量）和协议；
4. 用红笔圈出**你目前说不清**的那一段——那就是接下来要重点学的课。

**通过判据**：图上每一段都能回答「数据长什么样、多久一次、断了会怎样」。

## 6. 常见故障

| 症状 | 先怀疑的层 | 第一动作 |
|---|---|---|
| 完全没反应 | L1 电源/使能 | 量供电、看保险、看急停回路 |
| 只有某个方向不动 | L1 单路驱动 / L4 限幅 | 交换两路输出验证 |
| 动作延迟明显 | L3 链路/中间件 | 看 topic 频率与端到端时间戳 |
| 动作方向反了 | L4 符号约定 | 查坐标/映射表，不要先改硬件 |
| 松手继续动 | 反馈缺失 / 状态机 | 查反馈信号与使能条件 |
| 偶发丢帧 | L2 总线物理层 | 查终端电阻、接地、线束走向 |

> ⚠ 冲突提示：不同项目的「方向/符号约定」经常不一致（例如正角度对应上升还是下降）。以本项目**配置表 + 实测**为准，不以口头习惯为准。
