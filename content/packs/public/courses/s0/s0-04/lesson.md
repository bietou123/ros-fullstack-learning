# S0-04 · 网络：IP / 路由 / 端口 / SSH / 防火墙

> 验证状态：✅ `ip` / `ping` / `ss` / `ssh -V` 已在 Ubuntu 24.04（WSL2）实测；✅ 2026-11-05 nftables 实测（临时 table/chain/rule 的创建、列出与删除，测试后已清理）；⚠ 本机未安装 ufw / firewalld，这两条命令未实测。文中地址均为文档保留段或回环地址。

## 1. 现场类比

「连不上」这三个字，现场可以拆成四个完全不同的故障：

1. 网线/无线没通（链路层）；
2. IP 不在同一网段或没路由（网络层）；
3. 端口没监听或被防火墙挡住（传输层）；
4. 服务在但认证失败（应用层）。

**排障顺序必须从下往上**：先 `ip` 看地址，再 `ping` 看通路，再 `ss` 看端口，最后才查用户名密码。跳过前三步直接改配置，是最常见的无效劳动。

## 2. 核心概念

### 2.1 三个地址概念

| 概念 | 含义 | 命令 |
|---|---|---|
| IP 地址 | 主机在某网段的门牌号 | `ip -br addr` |
| 子网掩码/CIDR | 哪些地址算「同网段」 | `/24` 表示前 24 位是网络号 |
| 默认网关 | 去其他网段找谁 | `ip route` 里的 `default via` |

例：`192.0.2.10/24` 与 `192.0.2.20/24` 同网段，可直接通信；`198.51.100.5/24` 不同网段，必须经网关。

### 2.2 端口与监听地址

`ss -tlnp` 中的 Local Address：

- `127.0.0.1:8080`：只允许本机访问（最安全，也最容易被误判为「服务没起来」）；
- `0.0.0.0:8080`：所有网卡可访问；
- `[::]:8080`：IPv6 全部地址。

> 现场高频坑：服务日志写 `listening on 127.0.0.1:8080`，远程当然连不上。改监听地址，不要先怀疑网络。

### 2.3 SSH 最小知识

```bash
ssh -V                                  # 客户端版本
ssh user@192.0.2.10                     # 密码或密钥登录（占位地址）
ssh -p 2222 user@192.0.2.10             # 非默认端口
ssh -i ~/.ssh/id_ed25519 user@host      # 指定私钥
```

免密登录三步：

```bash
ssh-keygen -t ed25519 -C "robot-ops"    # 生成密钥（一路回车，可设 passphrase）
ssh-copy-id user@192.0.2.10             # 把公钥装到对方 authorized_keys
ssh user@192.0.2.10                     # 不再需要密码
```

私钥权限必须是 `600`，否则 OpenSSH 会拒绝使用。

### 2.4 防火墙

Ubuntu 常用 ufw，CentOS/RHEL 常用 firewalld。**先查状态再改规则**：

```bash
sudo ufw status verbose          # Ubuntu
sudo firewall-cmd --list-all     # firewalld
sudo nft list ruleset            # nftables
```

> ⚠ 冲突提示：不同发行版默认防火墙工具不同，网上教程经常混用。按目标机器的发行版选命令，不要直接照抄。

## 3. 可复制命令 / 代码

```bash
# 1) 看自己的地址与路由
ip -br addr
ip route

# 2) 回环连通性（不依赖外部网络）
ping -c 2 127.0.0.1

# 3) 看端口监听
ss -tlnp | head

# 4) SSH 客户端版本
ssh -V
```

## 4. 动手实验

**目标（25 分钟）**：在两台可达的机器之间完成一次「地址 → 通路 → 端口 → 登录」的完整验证（没有第二台机器时，可用本机回环 + 自测端口代替，学的是顺序）。

1. 在 A 机执行 `ip -br addr`，记下地址与网段；
2. 在 B 机 `ping A的地址`，确认通路；
3. 在 A 机起一个临时监听：`python3 -m http.server 8000 --bind 0.0.0.0`；
4. 在 B 机 `curl -I http://A的地址:8000`，返回 `HTTP/1.0 200 OK` 即通；
5. 回到 A 机把绑定改成 `127.0.0.1` 再试，体会「同一条网络，不同监听地址」的差别；
6. 有条件时用 `ssh` 登录 A 机，执行完退出。

**通过判据**：能口述「连不上」的四种原因，并说出每一步用哪条命令排除。

## 5. 自动检查

「实验」页签执行：

```bash
ip -br addr | grep -q 'UP'
ip route | grep -q 'default'
ping -c 2 -W 1 127.0.0.1
```

三条都返回 0 即通过。防火墙与 SSH 登录需要两台机器，本课程不做自动检查，避免伪造结果。

## 6. 常见故障

| 症状 | 可能原因 | 验证命令 |
|---|---|---|
| `ping` 不通 | 网段/网关/链路 | `ip route`、`ip link` |
| 能 ping 通但端口连不上 | 服务未监听/绑定回环/防火墙 | `ss -tlnp` |
| `Connection refused` | 端口没有进程监听 | `ss -tlnp \| grep 端口` |
| `Connection timed out` | 被防火墙丢包或路由不通 | `ip route`、`nft list ruleset` |
| SSH `Permission denied (publickey)` | 公钥没装、权限过宽 | `ls -l ~/.ssh`、`journalctl -u ssh` |
| SSH 很慢才连上 | DNS 反解超时 | 服务端 `UseDNS no`（改前确认安全要求） |
