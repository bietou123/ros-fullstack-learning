# S0-07 · 机器人四层架构与数据流

> 验证状态：概念与排障方法课，无强制命令；不涉及客户数据。

## 1. 现场类比

同一个「动臂不动」，可能是：

- 司机说「我推了」，但推杆传感器坏了；
- 推杆有数，但无线链路断了；
- 链路正常，但车端控制节点没启动；
- 节点在跑，但 CAN 没发出去；
- CAN 发了，但比例阀没电。

**四层架构的价值，是让你用 3 分钟把范围从「整车」缩到「一层」**，而不是拆线束拆半天。

## 2. 核心概念

### 2.1 四层定义（与 S0-01 五层模型的对应）

为保证排障口径统一，本课程后文使用四层：

| 层 | 包含 | 边界标志 |
|---|---|---|
| 交互层 | 座舱手柄/按钮、监控界面、会话 | 「指令是否产生」 |
| 计算层 | 工控机、Linux、ROS 节点、算法 | 「指令是否被接收与处理」 |
| 传输层 | CAN/以太网/串口、协议帧 | 「处理后是否发出」 |
| 执行层 | PLC/驱动器、电磁阀、液压、机械 | 「发出后是否动作」 |

反馈链路按相反方向走，但**同样分四层**：传感器 → 总线 → 计算 → 显示。

### 2.2 分层排障法（三步定界）

**第一步：找最靠近故障的已知正常点。**

- 界面显示指令值在变 → 交互层正常；
- 车端日志能打印收到的指令 → 传输层正常；
- `candump` 能看到控制帧 → 计算层到 CAN 正常。

**第二步：在「已知正常」和「已知异常」之间找一个可观测点**，逐步二分。不要从两端同时改。

**第三步：记录证据。** 每次判断必须留命令输出或截图，否则换班后无法复盘。

### 2.3 数据流的三条时间线

| 时间线 | 含义 | 现场意义 |
|---|---|---|
| 采样周期 | 传感器/手柄多久产生一次 | 20ms = 50Hz |
| 传输周期 | 总线上多久发一帧 | 与总线负载相关 |
| 控制周期 | 算法多久算一次 | 100Hz = 10ms，抖动要小 |

**三者不一致是正常的**，但必须明确谁等谁。若控制周期是 10ms 而输入 50Hz，控制节点要做「保持上次值 + 超时保护」，否则会重复执行旧值。

### 2.4 一个可复用的排障表

| 观测点 | 正常表现 | 命令/工具 |
|---|---|---|
| 手柄原始值 | 随推动连续变化 | 座舱诊断页/厂商工具 |
| 无线链路 | 心跳稳定、延迟可控 | ping / 链路状态页 |
| 车端接收 | 指令 topic 有频率 | `ros2 topic hz` / `rostopic hz` |
| 控制输出 | CAN 帧周期稳定 | `candump` |
| 执行反馈 | 角度/压力随动 | 传感器读数 / 仪表 |
| 机械动作 | 与指令方向一致 | 目视 + 限位开关 |

## 3. 可复制命令 / 代码

本课以方法为主，可在任意 Linux 机器演练「找可观测点」：

```bash
# 计算层：有哪些进程在跑
ps -ef | grep -E 'ros|python|bridge' | grep -v grep

# 传输层：哪些端口/接口在工作（以太网示例）
ss -tlnp | head

# 反馈层：系统日志里最近的错误
journalctl -n 50 --no-pager | grep -i -E 'error|fail' | head
```

## 4. 动手实验

**目标（20 分钟）**：针对一个假设故障，写出分层排障卡。

选择一个故障（例如「动臂上升无响应」），按下面模板填写：

```
故障现象：
已知正常点：            （证据：            ）
已知异常点：            （证据：            ）
二分观测点 1：          （证据：            ）
二分观测点 2：          （证据：            ）
结论所在层：
下一步验证：
```

**通过判据**：至少两个观测点有具体命令或界面位置，不能只写「检查一下」。

## 5. 自动检查

本节无自动实验。自查：

- [ ] 能背出四层顺序与每层边界标志；
- [ ] 能解释采样/传输/控制三种周期为什么会不一致；
- [ ] 排障卡上每个判断都有证据来源。

## 6. 常见故障

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 一上来就换件 | 浪费备件、掩盖真因 | 先找可观测点定界 |
| 同时改多处 | 无法判断哪步生效 | 一次只改一处，记录前后 |
| 只看最后一条日志 | 错过根因 | 找第一条错误 |
| 用「感觉」判断延迟 | 无法复现 | 用时间戳/频率量化 |
| 忽略反馈链路 | 开环误动作 | 指令与反馈成对检查 |
