# S0-08 · 安全底线：急停、看门狗、权限边界

> 验证状态：✅ `ulimit`、`systemctl`、`ps`、`ssh` 相关命令已在 Ubuntu 24.04（WSL2）实测；急停电路与液压侧为概念说明，**本课不涉及任何上机操作**。

## 1. 现场类比

远控挖掘机的安全不是「司机小心一点」，而是**三层独立的兜底**：

- 司机松手 → 手柄回中，指令归零（交互层兜底）；
- 无线断链 → 车端看门狗超时，输出归零（计算层兜底）；
- 任何一层失效 → 硬件急停直接切液压先导（执行层兜底）。

三层任何一层失效时，**另两层必须仍然有效**。这就是「安全不叠加在一条路径上」的含义。

## 2. 核心概念

### 2.1 急停的三种形态

| 形态 | 位置 | 作用对象 | 特点 |
|---|---|---|---|
| 硬件急停（E-Stop） | 车体、遥控器 | 液压先导 / 主电源 | 物理断开，不依赖软件 |
| 软件急停 | 界面、遥控器 | 控制节点输出 | 可记录、可远程，但依赖链路 |
| 保护性停止 | 控制器内部 | 动作限幅 | 超限触发，不叫停可继续 |

**关键区别**：软件急停不能替代硬件急停。软件急停失效的典型场景就是**链路已断**——而断链恰恰是最需要停车的时刻。

### 2.2 看门狗（Watchdog）

看门狗的核心是「**心跳断了我自己停**」，而不是「我等对方说停」。

```
正常情况下：控制节点每 20ms 收到指令 → 喂狗 → 继续输出
异常情况下：200ms 没收到指令 → 狗咬 → 输出归零 + 报错
```

三个必须明确的参数：

| 参数 | 含义 | 设错的后果 |
|---|---|---|
| 超时阈值 | 多久没输入算断链 | 太短→误停；太长→撞了才停 |
| 检测对象 | 检测哪个信号 | 检测了错的通道 → 形同没有 |
| 停车行为 | 咬了之后做什么 | 只报警不停车 → 无效 |

### 2.3 权限边界

现场账号不该做什么，比能做什么更重要：

- **普通账号不进入 docker 组**，除非明确需要（等于 root）；
- 不对 `~/.ssh` 用 777（私钥泄漏即等于设备被接管）；
- 不在生产机上开放无密码 `sudo`；
- ROS2 / CAN 的写权限收口到专用 group，而不是所有人都在 `dialout`。

### 2.4 一条安全链检查顺序

```
硬件急停 → 软件急停 → 看门狗 → 限幅 → 权限
```

检查时**永远从物理开始往软件走**：如果硬件急停按下去车不停，后面软件做得再好也没意义。

## 3. 可复制命令 / 代码

```bash
# 1. 系统里的服务与 watchdog 状态
systemctl is-system-running
systemctl list-units --type=service --state=running | head

# 2. 资源限制（进程能开多少、能不能 core dump）
ulimit -a

# 3. 谁能无密码 sudo
sudo -l -n 2>/dev/null || echo "需要密码或无权限"

# 4. SSH 私钥权限必须是 600
ls -l ~/.ssh 2>/dev/null || echo "无 ~/.ssh 目录"

# 5. 当前登录与最近登录
who
last -n 5
```

预期：`ulimit -a` 能列出 `max processes`、`open files` 等；`ls -l ~/.ssh` 中 `id_*` 私钥权限为 `-rw-------`。

## 4. 动手实验

**目标（20 分钟）**：写一张「三层兜底」安全检查表，针对你自己的目标设备。

按下表逐项确认，**每一项必须写「怎么验证」而不是「应该没问题」**：

```
【硬件急停】
位置：             按下后现象：           验证方式：
【软件急停】
触发方式：         记录在哪：             断链时是否仍有效：
【看门狗】
超时阈值：         检测对象：             触发后行为：
【限幅】
限位来源：         超限响应：             
【权限】
账号：             特殊组：               sudo 是否免密：
```

**通过判据**：安全表里至少有一项被查出问题（例如私钥 644、某账号在 docker 组），并能说出修复方法。

## 6. 常见故障

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 只做软件急停 | 断链时完全失去停车能力 | 必须有独立于链路的硬件急停 |
| 看门狗超时设得很大 | 撞了才停 | 按控制周期取 5–20 倍，实测延迟 |
| 看门狗只报警不停车 | 等于没有 | 触发后必须输出归零 |
| 私钥 `chmod 777` 图方便 | 同机任何账号可接管 | 保持 600，必要时用 `ssh-agent` |
| 人人都加进 docker 组 | 普通账号等同 root | 按需授权，用完移除 |
| 安全表只写「已检查」 | 无法复盘、无法交接 | 每项写验证命令与结果 |
