# S9-07 · 演示前 72 小时清单

> 验证状态：✅ 本机 Linux 实测了倒计时清单的结构完整性校验；⚠ 未执行真实演示倒计时，时间节点为通用工程实践示例。

## 1. 现场类比

演示当天早上发现：备用线缆没带、场地电源插座不匹配、设备里还是上周的旧固件。

这些都不是技术难题，是**清单没做、没人对**。最后 72 小时做的不是开发，是把不确定性一项项消掉。

## 2. 核心概念

### 2.1 为什么是 72 小时

| 提前量 | 还能做什么 | 再晚就难了 |
|---|---|---|
| T-72 | 换备件、改脚本、重新彩排 | 物流来不及 |
| T-48 | 发现流程问题、补人 | 返工时间不足 |
| T-24 | 修阻断性问题 | 只能赌 |
| T-2 | 开机自检、连接确认 | 出问题只能取消 |

**越晚发现问题，可选方案越少。**

### 2.2 倒计时清单（示例）

| 节点 | 必须完成 | 证据 |
|---|---|---|
| T-72 | 演示脚本冻结；备件/工具清单确认；人员分工 | 脚本版本号、清单签字 |
| T-48 | 全流程彩排第一遍；场地/网络确认；软件、配置、标定冻结 | 彩排记录、版本号 |
| T-24 | 彩排第二遍；设备开机自检；备用方案就绪 | 自检输出、Plan B 文档 |
| T-12 | 运输到场；环境适配（灯光、噪声、电源） | 到场照片/记录 |
| T-2 | 最终开机自检；连接测试；现场封场 | 自检 PASS、封场确认 |
| T-0 | 按脚本执行；记录问题 | 演示记录 |

### 2.3 每一项都要有负责人和状态

```
项目 | 负责人 | 截止节点 | 状态（未开始/进行中/完成） | 证据
```

**没有负责人的清单，只是一张愿望单。**

### 2.4 冻结原则

越接近演示，变更越少：

- T-48 后冻结软件、配置、标定版本；
- T-24 后**只修阻断性问题**，不做优化、不升级；
- 任何变更都要重新走一次关键流程并记录回滚点（S8-06）。

**「顺手升个级」是演示事故的常见起点。**

### 2.5 风险登记

列出前 3 项风险，每项写：

1. 触发条件（怎么知道它发生了）；
2. 影响（会损失哪一段演示）；
3. 应对（切备用链路 / 备用设备 / 跳过片段）。

### 2.6 最常失守的细节

- 备用线缆、转接头、电源；
- 现场电源规格与插头；
- 无线干扰（观众手机、同频设备）；
- 设备电量 / 耗材；
- 演示账号与权限（不要现场找密码）；
- 场地开放时间与封场许可。

## 3. 可复制命令 / 代码

```bash
# 校验倒计时清单：节点、事项、负责人是否齐全
python3 -c "items=[('T-72','备件与工具到位','owner_a'),('T-48','全流程彩排','owner_b'),('T-24','场地与环境确认','owner_c'),('T-2','设备开机自检','owner_d')]; missing=[x for x in items if not all(x)]; print('items=%d missing=%s'%(len(items),missing))"
```

预期：

```
items=4 missing=[]
```

四项都具备「节点、事项、负责人」，没有空缺。

## 4. 动手实验

**目标（30 分钟）**：为自己的演示建立一张可执行的 72 小时倒计时清单。

1. 按 T-72 / T-48 / T-24 / T-2 分组，每组至少 3 项；
2. 每项填负责人、截止节点、证据形式；
3. 用第 3 节代码校验结构完整性；
4. 列出前 3 项风险及应对；
5. 模拟「T-24 有一项未完成」，写明触发什么预案；
6. 写结论：哪一项最可能被拖延？谁来盯？

**通过判据**：清单结构完整、每项有负责人与证据；风险有明确应对；冻结规则写清楚。

python3 -c "items=[('T-72','备件与工具到位','owner_a'),('T-48','全流程彩排','owner_b'),('T-24','场地与环境确认','owner_c'),('T-2','设备开机自检','owner_d')]; missing=[x for x in items if not all(x)]; assert len(items)==4 and not missing; print('COUNTDOWN_OK')"

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 演示前夜还在改代码 | 无冻结规则 | T-48 冻结，之后只修阻断项 |
| 到场发现没电源 | 场地信息未确认 | T-48 前确认电源规格 |
| 备用方案用不上 | 未演练 | T-24 前实际切换一次 |
| 关键人员缺席 | 分工未落到人 | 每项写负责人与备份人 |
| 无线互相干扰 | 未做现场频段检查 | 到场后测信道，准备有线方案 |
| 现场找不到账号密码 | 凭据未按流程准备 | 使用受控凭据流程，不写进公开文档 |
| 演示超时 | 脚本未冻结/未计时 | 彩排计时，砍非核心片段 |
