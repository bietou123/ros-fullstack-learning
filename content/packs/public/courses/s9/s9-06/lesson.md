# S9-06 · 配置部署表解读（脱敏版）

> 验证状态：⚠ 本课为阅读课，无实验命令。示例表格为**完全虚构的脱敏模板**，不包含任何真实设备编号、IP、序列号、客户或内部系统信息；现场表以实际交付文档为准。

## 1. 现场类比

接手一台已经跑了两年的设备，前一位工程师已经离职，只留下一张部署表。

表上写着「配置版本 3.2」——可现场实际生效的是 3.1，因为环境变量覆盖了它。看不懂这张表，就不知道设备「本来应该是什么样」，也就无法判断「现在哪里不对」。

**配置部署表是设备的身份证 + 病历本。**

## 2. 核心概念

### 2.1 这张表解决什么问题

| 问题 | 表里对应的字段 |
|---|---|
| 这台设备装的是什么版本？ | 软件版本、镜像 tag |
| 用的是什么配置？ | 配置版本、生效层、关键参数 |
| 标定是谁做的、还准不准？ | 标定版本、日期、有效期 |
| 网络怎么接的？ | 网段占位、端口、时间源 |
| 出问题看哪里？ | 日志路径、服务单元名 |
| 改坏了怎么退？ | 回滚点、上一版本 |

### 2.2 字段分组

| 分组 | 典型字段 | 核对要点 |
|---|---|---|
| 设备身份 | 设备编号（占位）、型号、位置（脱敏） | 与现场实物一致 |
| 软件 | 发行版本、镜像 tag、依赖版本 | 不用 `latest` |
| 配置 | 配置版本、生效层、关键参数摘要 | **与实际生效值一致** |
| 标定 | 标定版本、日期、执行人、有效期 | 是否过期、是否重标 |
| 网络 | 网段占位、端口、隧道方式、时间源 | 端口最小化（S8-03） |
| 服务 | 单元名、是否自启、日志位置、保留期 | 与 `systemctl` 实际状态一致 |
| 数据 | 数据目录、容量、备份位置、回滚点 | 备份可读、回滚可执行 |
| 变更 | 时间、操作人、内容、原因、回滚点 | 每次变更必须回写 |

### 2.3 脱敏规则

公开或共享的部署表必须做到：

- 设备编号用 `<device-id>` 之类占位，**不写真实序列号**；
- 网段、地址用 `<site-net>` / `<device-ip>` 占位，**不写现场真实 IP**；
- 不写账号、口令、令牌、密钥；
- 不写客户名称、项目名称、报价；
- 截图前检查角落里的主机名、用户名、路径。

**脱敏版是给人看的模板，不是现场原件的复印件。**

### 2.4 核对「三件套」

| 项 | 是否一致 |
|---|---|
| 软件版本 | 实际运行版本 = 表中版本 |
| 配置版本 | **实际生效值**（含环境变量覆盖）= 表中版本 |
| 标定版本 | 加载的标定文件 = 表中版本且在有效期内 |

三者任一不一致，先修正再作业。**「表里写了」不等于「现场生效了」。**

### 2.5 常见误读

1. 把示例值当成现场值直接抄；
2. 只看配置文件，不看环境变量与命令行覆盖（S9-02）；
3. 配置版本一致，但标定文件已被替换；
4. 表里有服务，实际未启用或已失败；
5. 表长期不更新，变成「历史文档」。

### 2.6 变更记录怎么写

```
时间 | 操作人 | 改了什么 | 为什么改 | 影响范围 | 回滚点
```

没有回滚点的变更记录，是不完整的记录。

### 2.7 交接时先看哪几行

1. 软件 / 配置 / 标定三个版本；
2. 服务单元名与日志位置；
3. 回滚点与备份位置；
4. 最近三次变更；
5. 已知问题清单。

## 3. 脱敏字段模板

```text
设备：<device-id> / <model> / <site>
软件：<release-version>（镜像 tag：<image-tag>，禁止 latest）
配置：<config-version>（生效层：<layer>；关键参数：<summary>）
标定：<calib-version> / <date> / <operator> / 有效期至 <expiry>
网络：<site-net> / 端口 <port-list> / 隧道 <tunnel-type> / 时间源 <ntp-source>
服务：<unit-name>（自启：是/否）/ 日志 <log-path> / 保留 <days>
数据：<data-path> / 容量 <size> / 备份 <backup-location> / 回滚点 <rollback-point>
变更：<time> / <operator> / <change> / <reason> / <rollback-point>
```

所有尖括号内容都是占位符，**填报时替换为内部受控信息，公开场合保持占位**。

## 4. 动手实验（阅读任务）

**目标（30 分钟）**：为自己的一台设备写一份脱敏部署表，并核对一次。

1. 按 2.2 的分组收集字段；
2. 所有敏感字段改写成占位符；
3. 现场核对「三件套」：软件、配置、标定是否与表一致；
4. 找出至少一处表与实际的差异，分析原因；
5. 补一条变更记录，包含回滚点；
6. 写结论：这张表最不可靠的字段是哪一个？为什么？

**通过判据**：字段完整、无敏感信息；能指出至少一处表实差异并给出修正动作。

## 5. 自检问题

1. 你知道这台设备**实际生效**的配置版本吗，而不只是文件里的？
2. 标定文件的有效期是什么时候？过期后谁负责重标？
3. 服务失败时，日志在哪里、保留几天？
4. 上一次变更的回滚点是什么？演练过吗？
5. 这张表最近一次更新是什么时候？谁更新的？

有一题答不上来，这张表就还不能用于交接。

## 6. 常见故障 / 常见误判

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 表实版本不一致 | 变更后未回写 | 以实际为准，立即更新表 |
| 配置改了不生效 | 环境变量/命令行覆盖 | 打印生效值与来源（S9-02） |
| 标定突然失效 | 文件被替换或过期 | 核对标定版本与日期 |
| 服务「表里有、实际没有」 | 未启用或启动失败 | 查 `systemctl status` |
| 部署表出现敏感信息 | 直接复制现场原件 | 重新脱敏后再共享 |
| 交接后谁都说不清 | 变更记录缺失 | 补记录，建立回写纪律 |
| 回滚时找不到旧版本 | 回滚点未保留 | 保留 N-1，定期验证可回滚 |
