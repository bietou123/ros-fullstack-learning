# S9-05 · 验收检查点

> 验证状态：✅ 本机 Linux 实测了验收清单的通过率与关键项门禁计算；⚠ 具体验收阈值因项目而异，本课数值均为**教学示例**，实际以合同与技术协议为准。

## 1. 现场类比

交付会上双方都说「差不多了」。一周后现场反馈「这个不行、那个也不对」——因为从来没有一份写清判据、测过、签过字的验收清单。

**「做完了」不能靠感觉回答，要靠检查点回答。**

## 2. 核心概念

### 2.1 一个合格的检查点

| 属性 | 要求 |
|---|---|
| 可观察 | 能看到明确的现象 |
| 可测量 | 有数值或明确状态 |
| 可复现 | 同样的条件能再测一次 |
| 有判据 | 通过 / 不通过写清楚 |
| 有责任 | 谁测、谁确认、谁签字 |

**「动作顺畅」「界面友好」不是检查点，是形容词。**

### 2.2 分级与门禁

| 级别 | 含义 | 规则 |
|---|---|---|
| 关键（critical） | 安全、核心功能 | **一项不过，整体不通过** |
| 重要（major） | 影响使用但可规避 | 需限期整改 |
| 一般（minor） | 体验、文档 | 记录，可后续处理 |

通过率再高，关键项有一项失败也不能放行。

### 2.3 检查点的六个类别

| 类别 | 示例 |
|---|---|
| 功能 | 各动作、各模式是否可用 |
| 性能 | 延迟、精度、节拍 |
| 安全 | 急停、看门狗、限位 |
| 可靠性 | 连续运行、断电恢复、异常恢复 |
| 文档 | 操作手册、配置说明、SOP |
| 运维 | 日志、升级、回滚、备份 |

### 2.4 判据要写成可测句

| 不合格写法 | 合格写法（阈值按项目定义） |
|---|---|
| 动作顺畅 | 连续 20 次重复动作，定位误差 ≤ 项目阈值 |
| 响应快 | 端到端时延 P95 ≤ 项目阈值 |
| 很稳定 | 连续运行 N 小时无故障 |
| 安全可靠 | 急停触发后动力切断时间 ≤ 项目阈值 |

**测量条件也要写**：环境、负载、速度、操作者。

### 2.5 验收流程

```
预验收（内部）→ 现场验收（双方）→ 问题清单
    → 整改 → 复验 → 签字归档
```

每一步都要有记录。口头确认不算完成。

### 2.6 证据留存

数据、日志、截图、录像、签字单——**没有证据的通过，等于没有验收。**

### 2.7 容易漏测的边界

- 上电 / 断电 / 重启后的恢复；
- 网络中断与恢复；
- 传感器单点失效；
- 多人交替操作；
- 长时间连续运行；
- 极端环境（温度、光照、粉尘）。

## 3. 可复制命令 / 代码

```bash
# 验收清单：通过率 + 关键项门禁
python3 -c "items=[('estop','critical',True),('watchdog','critical',True),('latency','major',False),('log','minor',True)]; failed=[n for n,sev,p in items if not p]; critical_failed=[n for n,sev,p in items if sev=='critical' and not p]; rate=sum(p for _,_,p in items)/len(items)*100; print('pass_rate=%.0f failed=%s critical_failed=%s'%(rate,failed,critical_failed))"
```

预期：

```
pass_rate=75 failed=['latency'] critical_failed=[]
```

含义：通过率 75%，`latency` 未过但属于重要项；关键项全部通过，可以进入整改而不是整体否决。

## 4. 动手实验

**目标（35 分钟）**：为一个小项目写一份可执行的验收清单。

1. 按六个类别各写 1–2 个检查点，共不少于 8 项；
2. 每项标注级别（critical / major / minor）与判据；
3. 用第 3 节代码计算通过率与关键项状态；
4. 人为让一项关键检查点失败，确认整体结论变为「不通过」；
5. 写整改单：问题、责任人、期限、复验方式；
6. 写结论：最容易漏测的边界是什么？

**通过判据**：检查点可测可复现；关键项门禁逻辑正确；整改与复验路径明确。

## 5. 自动检查

```bash
python3 -c "items=[('estop','critical',True),('watchdog','critical',True),('latency','major',False),('log','minor',True)]; rate=sum(p for _,_,p in items)/len(items)*100; cf=[n for n,sev,p in items if sev=='critical' and not p]; assert rate==75 and not cf; print('ACCEPT_OK')"
```

预期输出 `ACCEPT_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 验收后频繁返工 | 检查点不可测 / 判据模糊 | 改成数值判据，重写清单 |
| 关键问题被通过率掩盖 | 未做关键项门禁 | 增加一票否决规则 |
| 双方对结果有争议 | 测量条件未约定 | 写明环境、负载、速度 |
| 复验总不过 | 整改无责任人/期限 | 整改单落到人和日期 |
| 连续运行才暴露的问题 | 验收时长不足 | 增加长稳测试项 |
| 断电后起不来 | 未测恢复流程 | 增加断电恢复检查点 |
| 文档缺失 | 验收未覆盖文档类 | 将文档列为正式检查点 |
