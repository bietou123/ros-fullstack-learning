# S9-01 · 远控全链路复盘

> 验证状态：✅ 本机 Linux 实测了链路时延预算与跟随误差计算；⚠ 各分段的实测数值为**教学示例值**，真实链路需按现场测量填写，不能直接引用。

## 1. 现场类比

操作员说：「我抬杆了，机器慢了半拍。」

这句话里没有可用信息——慢半拍可能是手柄采样、网络上行、网关转换、控制循环、伺服响应中的任何一段。**只有把链路拆开、每段量一次，才知道慢在哪里。**

## 2. 核心概念

### 2.1 全链路分段

```
操作端输入采样
  → 上行传输
  → 网关 / 协议转换
  → 控制循环
  → 执行器 / 伺服
  → 机构响应
```

反馈方向同理：传感器 → 下行 → 界面渲染。**每段都要能报出「耗时多少、周期多少、P95 多少」。**

### 2.2 时延如何变成误差

跟随误差的下限 ≈ 总时延 × 作业速度。

| 总时延 | 1 m/s | 2 m/s | 3 m/s |
|---:|---:|---:|---:|
| 50 ms | 5 cm | 10 cm | 15 cm |
| 73 ms | 7.3 cm | 14.6 cm | 21.9 cm |
| 150 ms | 15 cm | 30 cm | 45 cm |

**时延每增加 10 ms，2 m/s 下就多 2 cm 的滞后。** 精度要求越高，时延预算越紧。

### 2.3 均值会骗人，抖动才是体感

- 平均 73 ms、P95 120 ms：操作员感觉「有点延迟」；
- 平均 73 ms、P99 300 ms：操作员感觉「忽快忽慢、不敢操作」。

**至少报均值 + P95 + 最大值**，只报均值不算复盘。

### 2.4 必须同一时基

分段耗时靠相邻段的时间戳相减得到。各设备时钟不同步（S4-07）时，算出来会出现负延迟或周期性跳变。

**先确认时间同步，再谈分段耗时。**

### 2.5 时序图的画法

泳道图，每个角色一条泳道：

| 泳道 | 标注内容 |
|---|---|
| 操作端 | 采样时刻、发送时刻 |
| 网关 | 收到时刻、转发时刻、协议转换耗时 |
| 控制 | 周期开始/结束、指令生效时刻 |
| 执行器 | 收到指令、实际动作时刻 |
| 反馈 | 传感器采样、到达界面 |

在图上标出**故障观察点**（操作员说「慢半拍」的那个时刻），再对照各段耗时，才能定位。

### 2.6 复盘产出

一张时序图 + 一张分段耗时表 + 三个数字：总时延、P95、最大抖动。最后写清「最大的一段是谁、为什么、怎么改」。

## 3. 可复制命令 / 代码

```bash
# 全链路时延预算：分段耗时 → 总时延 → 跟随误差
python3 -c "chain=[('joystick',8),('uplink',25),('ctrl_loop',10),('servo',30)]; total=sum(t for _,t in chain); v=2.0; print('total_ms=%d lag_cm=%.1f'%(total,total/1000*v*100))"
```

预期：

```
total_ms=73 lag_cm=14.6
```

含义：总时延 73 ms，在 2 m/s 下理论滞后至少 14.6 cm。**这里的 8/25/10/30 ms 是教学示例值，现场必须换成实测值。**

## 4. 动手实验

**目标（40 分钟）**：为自己的远控链路画一张时序图，并算出跟随误差下限。

1. 列出链路的全部段，标出每段的测量点；
2. 每段至少测 100 次，记录均值、P95、最大值（无法实测的段明确标注「估算」）；
3. 确认所有测量点使用同一时基；
4. 用第 3 节的代码算总时延与工作速度下的滞后；
5. 找出耗时最大的一段，列出 2 个可能原因；
6. 画泳道时序图，标出故障时刻；
7. 写结论：瓶颈段、改进项、改进后预期时延。

**通过判据**：时序图完整；总时延与滞后计算正确；能指出瓶颈段并给出可验证的改进方向。

## 5. 自动检查

```bash
python3 -c "chain=[('joystick',8),('uplink',25),('ctrl_loop',10),('servo',30)]; total=sum(t for _,t in chain); lag=total/1000*2.0*100; assert total==73 and abs(lag-14.6)<0.1; print('LATENCY_OK')"
```

预期输出 `LATENCY_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 各段都正常但总延迟大 | 测量点缺失 / 时钟不同步 | 统一时基，补测缺的段 |
| 上行延迟忽高忽低 | 无线链路质量差、编码拥塞 | 看 P95 与丢包率，换信道 |
| 控制周期抖动大 | CPU 抢占、循环内日志 | 关高频日志，查负载 |
| 伺服响应慢 | 参数保守、负载过大 | 查伺服状态与负载率 |
| 反馈画面延迟 | 下行带宽不足、渲染慢 | 降分辨率，看渲染耗时 |
| 偶发几秒卡死 | 垃圾回收 / 网络重传 | 查 GC 日志与重传计数 |
| 延迟随距离明显变化 | 链路衰减、遮挡 | 做距离-延迟曲线 |
