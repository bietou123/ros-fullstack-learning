# S6-07 · 安全验收清单

> 验证状态：✅ 本课清单结构校验命令已在本机 Linux 实测；⚠ 未执行真实项目验收。清单模板为**教学示例**，实际项目须结合合同、法规与设备手册编写。

## 1. 现场类比

演示前 10 分钟，发现急停按钮的线还没接。所有人都在等，改也来不及。

验收清单不是形式主义，它解决的是：**人一忙就会漏，漏的那一项往往最要命。**

## 2. 核心概念

### 2.1 验收分五层

| 层级 | 检查什么 | 示例 |
|---|---|---|
| 硬件安全 | 急停、限位、防护、接地 | 急停按下后动力切断 |
| 软件安全 | 状态机、看门狗、限幅 | 断线 1 s 内停机 |
| 通信 | 延迟、丢包、断线恢复 | 丢包 5% 时仍能安全停机 |
| 数据 | 时间戳、单位、坐标系 | 时间戳单调、单位一致 |
| 操作流程 | 开机、复位、交接 | 复位需人工确认 |

### 2.2 每一项必须可判定

| 不合格的写法 | 合格写法 |
|---|---|
| 动作尽量平稳 | 阶跃响应超调 < 5% |
| 延迟较低 | 端到端 P99 < 150 ms |
| 断线处理正常 | 断线后 1 s 内输出归零并进入 Fault |
| 急停有效 | 按下急停，动力切断时间 < 100 ms |
| 数据准确 | 触地 20 点 RMS < 2 cm |

**「尽量」「正常」「良好」都不是判据。** 判据要能被第三方复现。

### 2.3 每项要有证据

| 证据 | 用途 |
|---|---|
| 日志（带时间戳） | 证明行为发生及时间 |
| 截图/录屏 | 证明界面状态 |
| 测试记录表 | 记录方法、结果、执行人 |
| 测量数据 | 支撑数值判据 |

没有证据的「已检查」，验收时等于没做。

### 2.4 清单结构

每项至少五个字段：

```
类别 | 检查项 | 方法 | 判据 | 证据
```

再加上：执行人、日期、结果（通过/不通过/不适用）、备注。

**「不适用」也要写理由**，不能空着。

## 3. 可复制命令 / 代码

```bash
# 校验清单结构：每项必须包含 item / method / criteria / evidence 四个字段
python3 -c "chk=[{'item':'estop','method':'press','criteria':'power_off_lt_100ms','evidence':'log'},{'item':'watchdog','method':'kill','criteria':'stop_lt_1s','evidence':'log'}]; print('n=%d all_fields=%s'%(len(chk),all(k in i for i in chk for k in ('item','method','criteria','evidence'))))"
```

预期：`n=2 all_fields=True`。字段缺失时结果为 `False`，清单不完整。

## 4. 动手实验

**目标（30 分钟）**：产出一张可执行的 20 项安全验收清单。

1. 按五层各列 4 项，共 20 项；
2. 每项写清方法、判据、证据类型；
3. 检查判据是否可测量：含有数字、单位或明确的通过/不通过条件；
4. 标出必须现场实测的项目（如急停、断线、限位）；
5. 用本课代码校验结构完整性；
6. 写结论：哪些项风险最高？哪些项依赖其他团队配合？

**通过判据**：20 项齐全、字段完整、判据可复现，且至少 5 项为现场实测。

## 6. 常见故障 / 常见遗漏

| 问题 | 后果 | 修正 |
|---|---|---|
| 判据写「正常/良好」 | 无法判定，验收扯皮 | 改成可测数值 |
| 只查软件不查硬件 | 急停失效无人发现 | 增加硬线回路实测 |
| 只测正常流程 | 故障行为未验证 | 补故障注入项 |
| 没有证据 | 事后无法追溯 | 日志/截图/记录表 |
| 「不适用」不写理由 | 被当成已通过 | 必须注明原因 |
| 验收人未签字 | 责任不清 | 执行人 + 复核人签字 |
| 清单一次性使用 | 下次从零开始 | 模板化并版本管理 |
