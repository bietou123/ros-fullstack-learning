# S6-03 · 状态机设计

> 验证状态：✅ 本课状态转移命令已在本机 Linux 实测；⚠ 未与实机控制程序联调，状态与事件命名为**教学示例**。

## 1. 现场类比

操作手连点两次「启动」，机器执行了两遍初始化；或者故障还没复位，一按启动就动了。

这类问题靠 `if` 堆叠越来越难维护。**状态机的作用是：把「现在能不能做这件事」变成一个可检查的问题。**

## 2. 核心概念

### 2.1 四个要素

| 要素 | 含义 | 例子 |
|---|---|---|
| 状态 state | 当前处于什么阶段 | Idle / Running / Fault |
| 事件 event | 发生了什么 | start / stop / fault / reset / estop |
| 转移 transition | 什么事件让状态怎么变 | Running + stop → Idle |
| 守卫 guard | 转移的附加条件 | 急停未复位时禁止 start |

进入/退出动作（entry/exit action）也要定义：进入 Running 时开使能，退出时关使能。

### 2.2 三态机（最小可用）

```
        start(guard: 无故障)
 Idle ─────────────────▶ Running
   ▲                        │
   │ reset                  │ stop
   │                        ▼
   └────────────────────── Idle
   ▲
   │                fault（任何状态）
   └──────────── Fault ◀─────────
```

| 当前 | 事件 | 守卫 | 下一状态 | 动作 |
|---|---|---|---|---|
| Idle | start | 急停已复位、无故障 | Running | 使能输出 |
| Running | stop | — | Idle | 关闭输出 |
| Running | fault | — | Fault | 立即停机、上报 |
| Fault | reset | 故障已消除 | Idle | 清故障、保持输出关闭 |
| 任意 | estop | — | Fault/EStop | 硬件断使能 |

### 2.3 三条铁律

1. **状态唯一**：整机只允许一个权威状态源，其他节点订阅，不各自维护；
2. **非法转移必须拒绝并记录**：不能「悄悄忽略」，否则现场查不出为什么没动作；
3. **故障恢复必须显式**：`Fault → Running` 不允许直连，必须经过 `reset`，且复位时输出保持关闭。

### 2.4 实现方式

- 用枚举/常量表示状态，不用裸字符串；
- 用转移表（字典）集中管理，不散落在各处 `if`；
- 每次转移打日志：时间、源状态、事件、目标状态、守卫结果；
- 状态作为话题/服务对外发布，便于监控和测试。

## 3. 可复制命令 / 代码

```bash
# 三态机：非法转移被拒绝（fault 状态下再 start 仍保持 fault）
python3 -c "T={('idle','start'):'running',('running','stop'):'idle',('running','fault'):'fault',('fault','reset'):'idle'}; s='idle'; seq=[s]; [(s:=T.get((s,e),s), seq.append(s)) for e in ('start','fault','start','reset')]; print(seq)"
```

预期：`['idle', 'running', 'fault', 'fault', 'idle']`。注意第 4 个元素仍是 `fault`——**非法 start 被拒绝**，不是静默忽略后跳到别处。

## 4. 动手实验

**目标（40 分钟）**：写出一张完整的三态转移表，并用代码验证。

1. 列出你的系统真实需要的状态（至少 Idle / Running / Fault）；
2. 列出所有事件，包括急停、看门狗超时、通信中断；
3. 填转移表：当前状态 × 事件 → 下一状态 + 动作 + 守卫；
4. 标出所有非法转移，明确处理方式（拒绝 + 日志）；
5. 用本课代码仿真一条事件序列，包括至少一次非法事件；
6. 写结论：哪些转移最容易漏？故障恢复路径是否安全？

**通过判据**：转移表覆盖所有状态与事件组合（无空白格），非法转移有明确处理，`Fault` 不能直接回 `Running`。

## 5. 自动检查

```bash
python3 -c "T={('idle','start'):'running',('running','stop'):'idle',('running','fault'):'fault',('fault','reset'):'idle'}; s='idle'; seq=[s]; [(s:=T.get((s,e),s), seq.append(s)) for e in ('start','fault','start','reset')]; assert seq==['idle','running','fault','fault','idle']; print('FSM_OK')"
```

预期输出 `FSM_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 重复启动执行两次 | 事件未去重、状态未及时切换 | 加事件锁/幂等处理 |
| 故障未复位就能启动 | Fault 直接连到 Running | 转移表加守卫 |
| 多节点显示状态不一致 | 各节点各自维护状态 | 单一状态源 + 订阅 |
| 某事件完全没反应 | 非法转移被静默忽略 | 拒绝也要打日志 |
| 急停后自动恢复 | 复位逻辑错误 | 恢复必须显式确认 |
| 状态跳变顺序异常 | 事件队列乱序/丢失 | 带序号、时间戳，拒绝过期事件 |
| 重启后状态不对 | 未定义初始状态 | 上电固定进入 Idle 并自检 |
