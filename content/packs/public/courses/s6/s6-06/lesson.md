# S6-06 · 故障注入与恢复测试

> 验证状态：✅ 本课数据超时与连续丢帧统计命令已在本机 Linux 实测；⚠ 未做真实断线/断电/网络注入测试。注入命令（拔线、`tc netem`、断电）**必须先在仿真或隔离环境验证，不得直接在生产设备上做**。

## 1. 现场类比

演示前一天，操作端网线被踢掉。系统原地保持最后速度，直到有人拔了电源。

如果之前测过「网线断开」，这个行为就会被发现并改成「超时停机」。**没测过的故障，一定会在最不方便的时候出现。**

## 2. 核心概念

### 2.1 至少覆盖六类故障

| 类别 | 典型注入 | 期望的安全行为 |
|---|---|---|
| 传感器断线 | 拔线、屏蔽数据 | 超时检测 → 停止输出 → 上报 |
| 网络丢包/延迟 | `tc netem`（隔离环境） | 心跳超时 → 安全停机 |
| 进程崩溃 | `kill -9` | 看门狗触发 → 输出归零 |
| 电源/急停 | 断电、按急停 | 硬件断动力，手动复位 |
| 输入异常 | NaN、越界、抖动值 | 输入校验拒绝 → 保持安全输出 |
| 存储/资源 | 磁盘写满、CPU 打满 | 降级或停机，不产生错误动作 |

### 2.2 每类故障要记录四件事

| 记录项 | 问题 |
|---|---|
| 检测时间 | 多久发现？ |
| 安全行为 | 停下来了吗？怎么停的？ |
| 恢复方式 | 自动还是手动？ |
| 恢复后状态 | 是否回到 Idle、输出是否关闭？ |

**只记录「停了」不够**，要记录「从故障发生到安全状态用了多久」。

### 2.3 测试原则

1. **先仿真，后实机**；实机测试必须有人监护、有急停、有限速；
2. **一次只注入一个故障**，否则无法归因；
3. **注入要真实**：直接改代码里一个布尔值，不算测断线；
4. **重复测试**：同一故障至少 3 次，看是否稳定；
5. **留证据**：日志、时间戳、视频，验收时要能复现。

### 2.4 恢复测试同样重要

很多系统「故障时能停」，但「故障消除后」出问题：

- 自动重连后直接恢复运行；
- 旧指令队列被重新执行；
- 状态停留在中间态；
- 传感器恢复后数据时间戳仍是旧的。

**恢复后第一件事是确认处于 Idle、输出关闭，再重新使能。**

## 3. 可复制命令 / 代码

```bash
# 数据时间戳老化检测：超过 0.2 s 判定为陈旧
python3 -c "now=10.0; stamps=[9.95,9.7]; ages=[round(now-t,2) for t in stamps]; print('ages=%s stale=%s'%(ages,[x>0.2 for x in ages]))"

# 连续丢帧计数：只有连续超时才判失联，避免单次抖动误触发
python3 -c "misses=[0,1,0,1,1,1,1]; runs=[]; c=0; [(c:=c+1 if m else 0, runs.append(c)) for m in misses]; print('max_consecutive_miss=%d'%max(runs))"
```

预期：`ages=[0.05, 0.3] stale=[False, True]`；最大连续丢帧 `4`。**单次丢帧不触发，连续超时才触发。**

## 4. 动手实验

**目标（40 分钟）**：为六类故障各写一条测试用例，并在安全环境中执行至少两类。

1. 按上表列出六类故障，每类写：注入方法、预期检测时间、预期安全行为、恢复方式；
2. 选择两类可以在本地安全执行的（如数据超时、进程崩溃）；
3. 执行并记录：故障时刻、检测时刻、停机时刻、恢复时刻；
4. 检查恢复后是否处于 Idle、输出是否为零、旧队列是否清空；
5. 对不通过的项，写清是「检测不到」还是「检测到但行为不对」；
6. 汇总成 6 类故障报告。

**通过判据**：六类都有用例；已执行的两类有完整时间线；恢复后状态经过确认。

## 5. 自动检查

```bash
python3 -c "misses=[0,1,0,1,1,1,1]; runs=[]; c=0; [(c:=c+1 if m else 0, runs.append(c)) for m in misses]; assert max(runs)==4; print('FAULT_TEST_OK')"
```

预期输出 `FAULT_TEST_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 故障时没停 | 没有超时检测、状态机未处理 | 补看门狗与 Fault 转移 |
| 停了但很久才停 | 阈值过大、检测周期长 | 缩短检测周期，重算预算 |
| 恢复后直接运行 | 恢复逻辑跳过使能 | 强制恢复只回 Idle |
| 恢复后执行旧指令 | 队列未清空 | 恢复时清空命令队列 |
| 单次丢包就停机 | 未用连续超时判定 | 加连续 N 次条件 |
| 测试结果不稳定 | 注入不真实、并发因素多 | 一次一个故障，重复 3 次 |
| 现场复现不了实验室结果 | 网络/负载环境不同 | 记录环境差异，现场补测 |
