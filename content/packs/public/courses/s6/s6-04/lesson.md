# S6-04 · 三级停机与急停链路

> 验证状态：✅ 本课停机时间预算命令已在本机 Linux 实测；⚠ 未实机测试急停回路。具体停机类别、回路设计与合规要求**必须由有资质人员按现场法规与设备手册确认**。

## 1. 现场类比

急停按钮按下去了，机器还在动半秒才停。操作手以为按钮坏了。

其实按钮没坏——**按钮只是链路的起点**，中间还有安全继电器、驱动器、控制软件。每一级都有延迟，加起来就是那半秒。停机距离 = 速度 × 这半秒。

## 2. 核心概念

### 2.1 三级停机

| 级别 | 触发 | 行为 | 谁说了算 |
|---|---|---|---|
| 一级：急停 | 急停按钮、安全门、安全光幕 | 按设计切断动力或受控后断电 | **硬件安全回路** |
| 二级：保护停机 | 超速、超限、通信中断、看门狗 | 受控减速停机，保留状态与日志 | 控制器 |
| 三级：正常停机 | 操作手主动停机 | 按斜坡正常减速 | 控制软件 |

**软件可以触发二级/三级，但不能替代一级。** 一级必须有独立于操作系统的硬线回路。

### 2.2 停机类别（IEC 60204-1 概念）

| 类别 | 行为 | 适用 |
|---|---|---|
| 0 类 | 立即切断动力 | 风险高、可承受急停冲击 |
| 1 类 | 受控减速后再断电 | 高速大惯量设备 |
| 2 类 | 受控停机但保留动力 | 需要保持位置/抱闸 |

选哪一类由风险评估决定，不是「越急越好」。大惯量设备直接断电可能造成机械冲击。

### 2.3 急停链路

```
急停按钮（双通道） → 安全继电器/安全 PLC → 驱动器 STO / 主接触器
                                     └→ 控制层收到「急停已触发」事件
```

要点：

- **双通道 + 交叉监测**，单点失效不能导致失效安全；
- 断使能优先于「发一条停止命令」；
- 控制层收到事件后进入 Fault，**但停机动作不依赖软件是否收到**；
- 复位必须手动，复位后输出保持关闭，需重新使能。

### 2.4 停机距离预算

```
停机距离 ≈ 速度 × (检测延迟 + 回路延迟 + 驱动响应 + 减速时间)
```

示例（教学值）：检测 10 ms + 安全继电器 20 ms + 驱动 30 ms = 60 ms；速度 1 m/s → 仅响应阶段就前进 6 cm，还没算减速过程。

**这就是为什么急停按钮附近不能站人，以及为什么工作区域要留安全距离。**

## 3. 可复制命令 / 代码

```bash
# 停机响应时间预算：检测 + 继电器 + 驱动
python3 -c "d=[0.010,0.020,0.030]; print('total_ms=%.0f stop_dist_cm=%.1f'%(sum(d)*1000,sum(d)*1.0*100))"

# 不同速度下仅「响应阶段」的前进距离
python3 -c "t=0.06; print([(v,round(v*t*100,1)) for v in (0.5,1.0,2.0)])"
```

预期：总响应 60 ms，1 m/s 时前进 6.0 cm；速度翻倍，距离翻倍。

## 4. 动手实验

**目标（35 分钟）**：画出你设备的停机链路，并算清最坏停机距离。

1. 从急停按钮开始，逐级画出到执行器的链路；
2. 标注每一级是硬件还是软件、单通道还是双通道；
3. 查手册或实测每一级延迟，填入预算表；
4. 计算常用速度下的响应距离与总停机距离；
5. 找出链路中的单点故障，判断是否可接受；
6. 写结论：当前设计属于哪一类停机？复位流程是什么？多久测试一次？

**通过判据**：链路图完整、每级延迟有来源、单点故障已标出，且复位必须人工确认。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 急停后仍缓慢移动 | 只断了软件使能，动力未切 | 检查安全回路与驱动 STO |
| 急停按钮无反应 | 回路未接、触点氧化、通道失效 | 用万用表分段测量，做双通道测试 |
| 复位后机器自动动 | 复位逻辑直接恢复运行 | 复位只允许回 Idle，需重新使能 |
| 偶尔误触发急停 | 线缆松动、干扰、双通道不同步 | 查接线、屏蔽、通道同步时间 |
| 不同设备停机距离差别大 | 响应时间不同、速度不同 | 逐台测延迟，更新安全距离 |
| 急停后无日志 | 控制层没收到事件 | 增加状态上报，但不能依赖它停机 |
| 测试时「按一下看看」 | 未按规程测试 | 制定定期测试流程并留证 |
