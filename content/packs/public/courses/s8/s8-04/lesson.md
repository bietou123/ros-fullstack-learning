# S8-04 · 日志体系与排障

> 验证状态：✅ 本机 Linux 实测了 `journalctl` 查询与 JSON 日志过滤命令；⚠ 未接入集中式日志平台，架构建议为通用实践。

## 1. 现场类比

故障发生了，日志里只有一行 `error`，没有时间、没有模块、没有上下文。

**日志不是写给自己看的，是写给三天后半夜被叫起来的自己看的。**

## 2. 核心概念

### 2.1 一条有用的日志包含什么

| 字段 | 作用 |
|---|---|
| 时间戳 | 与事件对时（UTC + 本地） |
| 级别 | DEBUG / INFO / WARN / ERROR / FATAL |
| 组件 | 哪个节点/模块 |
| 关联 ID | 把同一次请求/任务串起来 |
| 上下文 | 关键参数、目标、错误码 |
| 结果 | 成功/失败、耗时 |

**没有关联 ID 的分布式日志，基本等于没有。**

### 2.2 结构化日志

推荐 JSON 行格式，字段固定，便于检索：

```json
{"ts":"2026-01-01T00:00:00Z","lvl":"ERROR","comp":"bridge","corr":"t-001","msg":"timeout","peer":"driver"}
```

比 `print("error")` 多花几秒钟，排障时省几小时。

### 2.3 日志级别怎么用

| 级别 | 用于 |
|---|---|
| DEBUG | 开发定位，生产默认关闭 |
| INFO | 关键状态变化、启动参数摘要 |
| WARN | 可恢复异常、降级 |
| ERROR | 功能失败、需要关注 |
| FATAL | 无法继续，进程退出 |

**控制循环里禁止高频日志**（见 S4-06），否则 I/O 就是抖动源。要统计就计数，定期汇总输出。

### 2.4 轮转与保留

- 单文件有上限，按大小/时间轮转；
- 保留天数按现场要求，避免磁盘写满；
- 磁盘写满要能触发告警与安全降级（S6-06 的故障类之一）；
- 关键事件另存一份，防止被轮转覆盖。

### 2.5 安全与隐私

- 不记录密码、令牌、密钥；
- 不记录完整身份证/手机号等个人信息；
- 内网地址、设备序列号按需脱敏；
- 日志文件权限限制，远程传输加密。

**日志泄露和密码泄露一样严重。**

### 2.6 排障检索顺序

```
时间窗口 → 组件 → 级别(ERROR/WARN) → 关联 ID → 上下游时间段
```

先缩小范围，再顺着关联 ID 看整条链路，最后对比故障前后。

## 3. 可复制命令 / 代码

```bash
# 查看最近日志与磁盘占用
journalctl -n 5 --no-pager
journalctl --disk-usage

# 按服务过滤（服务名换成自己的）
journalctl -u <service> --since "10 min ago" --no-pager | tail -n 20

# 解析 JSONL 日志，筛出 ERROR
python3 -c "import json; L=[{'ts':1,'lvl':'INFO','msg':'start'},{'ts':2,'lvl':'ERROR','msg':'timeout'}]; open('/tmp/l.jsonl','w').write(chr(10).join(json.dumps(x) for x in L)); rows=[json.loads(s) for s in open('/tmp/l.jsonl')]; print(len(rows),[r['msg'] for r in rows if r['lvl']=='ERROR'])"
```

预期：日志条目、磁盘占用；JSON 结果 `2 ['timeout']`。

## 4. 动手实验

**目标（35 分钟）**：建立最小可用日志规范，并用它定位一次「假故障」。

1. 为你的服务定义日志字段（至少含时间、级别、组件、关联 ID、消息）；
2. 规定每个级别的使用场景；
3. 设置轮转策略与保留天数；
4. 检查现有日志是否含有敏感信息，清理；
5. 人为制造一次超时，用「时间窗口 + 组件 + 关联 ID」定位；
6. 写结论：从故障到定位用了多久？缺了哪个字段？

**通过判据**：能在 5 分钟内从日志定位到具体组件与错误原因；日志无敏感信息。

## 5. 自动检查

```bash
python3 -c "import json; L=[{'ts':1,'lvl':'INFO','msg':'start'},{'ts':2,'lvl':'ERROR','msg':'timeout'}]; open('/tmp/l.jsonl','w').write(chr(10).join(json.dumps(x) for x in L)); rows=[json.loads(s) for s in open('/tmp/l.jsonl')]; errs=[r for r in rows if r['lvl']=='ERROR']; assert len(rows)==2 and errs[0]['msg']=='timeout'; print('LOG_OK')"
```

预期输出 `LOG_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 日志找不到故障时刻 | 无时间戳/时区混用 | 统一 UTC，带毫秒 |
| 日志太多淹没关键行 | 循环内高频打印 | 降级为计数汇总 |
| 磁盘写满导致停机 | 无轮转/无保留策略 | 配置 rotation，加告警 |
| 无法串联一次任务 | 无关联 ID | 入口生成 corr id，逐层透传 |
| 日志里有密码 | 直接打印请求体 | 脱敏后再记录 |
| 多机日志对不上 | 时钟未同步 | 见 S4-07 NTP/PTP |
| 重启后日志丢失 | 只输出到终端 | 接入 journald/文件/集中平台 |
