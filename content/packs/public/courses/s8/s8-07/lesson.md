# S8-07 · 现场开机流程 SOP

> 验证状态：✅ 本机 Linux 实测了 SOP 卡的结构化校验命令；⚠ 真实设备的上电顺序、安全回路自检与场地条件**未实测**，SOP 内容为通用工程实践，落地以现场电气负责人签署的版本为准。

## 1. 现场类比

同一型号两台设备：A 现场每天开机十分钟就绪；B 现场每天要先排查两次报警，先上电后开电脑、标定没加载、安全自检跳过去直接动——**不是设备差，是开机没有顺序。**

开机不是「按电源」，是一条有先后、有确认点、失败就停的流程。

## 2. 核心概念

### 2.1 一张 SOP 卡必须有什么

| 要素 | 说明 |
|---|---|
| 前置条件 | 场地、电源、气源、人员清场、防护到位 |
| 步骤与顺序 | 每一步做什么、由谁做 |
| 每步验证点 | 怎么确认这步真的成功了 |
| 失败处理 | 哪步不过就停在哪里、找谁 |
| 时间预算 | 正常多久完成，超时说明有问题 |
| 版本与签名 | 改过什么、谁批准的 |

**没有验证点的步骤，等于没做。**

### 2.2 开机顺序原则：由安全到功能、由底层到上层

```
安全回路 / 急停自检
  → 电源 / 气源
  → 感知（相机、激光、IMU）
  → 计算与网络
  → 控制与执行
  → 人机界面 / 远程接入
```

关机按**相反顺序**执行。顺序颠倒的典型后果：控制节点先起、拿不到传感器数据，于是进入故障态；或者界面先起，操作员看到「未就绪」就以为设备坏了。

### 2.3 每次开机都必须验证的项

| 项 | 验证方式 |
|---|---|
| 急停与安全回路 | 按下急停，确认动力切断且无法进入工作模式 |
| 看门狗 | 模拟通信中断，确认超时保护生效（S6-05） |
| 限位 / 软限位 | 读取状态，确认位置与标定一致 |
| 时间同步 | 各节点时间偏差在允许范围内（S4-07） |
| 标定与 TF | 版本号与配置一致，TF 树完整 |
| 关键话题频率 | 与实际传感器标称频率对照 |
| 通信链路 | 远程/总线链路状态正常 |

### 2.4 开机自检要自动化

手工逐项点检容易漏。用脚本输出 `PASS/FAIL` 清单：

- 任一 `FAIL` → **禁止进入工作模式**，不是「先干着看」；
- 自检结果留档，便于对比「今天和昨天差在哪」；
- 自检项与 SOP 卡一一对应，避免文档和实际脱节。

### 2.5 现场环境先于设备

- 电源电压、气源压力在范围内；
- 温度、湿度、粉尘不影响传感器；
- 线缆无破损、接插件锁紧；
- 作业半径内无人、无杂物，防护设施到位；
- 通讯信号覆盖正常（远程场景）。

**设备再正常，环境不对也不能开机。**

### 2.6 SOP 是活的文档

设备、软件、标定、场地任何一项变化，SOP 都要更新并重新演练。版本号、变更记录、批准人缺一不可。

## 3. 可复制命令 / 代码

```bash
# 校验一张 SOP 卡的结构是否完整
python3 -c "import json; card={'version':'2.1','steps':['estop_check','power_on','sensors','network','control','hmi'],'time_budget_min':10,'abort_on_fail':True}; req=['version','steps','time_budget_min','abort_on_fail']; miss=[k for k in req if k not in card]; print('steps=%d first=%s abort=%s miss=%s'%(len(card['steps']),card['steps'][0],card['abort_on_fail'],miss))"
```

预期：

```
steps=6 first=estop_check abort=True miss=[]
```

含义：6 个步骤、第一步是急停自检、失败即中止、必填字段无缺失。

## 4. 动手实验

**目标（30 分钟）**：产出一张自己的开机 SOP 卡，并完整走一遍。

1. 按 2.2 的顺序列出步骤，每一步写清验证点；
2. 设定时间预算与「超时怎么办」；
3. 规定任一验证失败时的停止点与联系人；
4. 用第 3 节的命令校验卡片结构完整；
5. 实际按卡走一遍（可先在仿真/桌面环境），记录总耗时；
6. 人为让一步验证失败，确认流程真的停住，而不是继续往下走；
7. 写结论：哪一步最耗时？哪一步最容易漏？

**通过判据**：SOP 卡结构完整；实际走完一遍且耗时在预算内；失败注入时流程停在预期位置。

## 5. 自动检查

```bash
python3 -c "import json; card={'version':'2.1','steps':['estop_check','power_on','sensors','network','control','hmi'],'time_budget_min':10,'abort_on_fail':True}; req=['version','steps','time_budget_min','abort_on_fail']; miss=[k for k in req if k not in card]; assert card['steps'][0]=='estop_check' and card['abort_on_fail'] and not miss; print('SOP_OK')"
```

预期输出 `SOP_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 开机后设备不动 | 急停未复位 / 安全回路未就绪 | 查急停状态与安全回路指示 |
| 控制节点一起步就报错 | 顺序颠倒，传感器未就绪 | 调整启动顺序，加依赖等待 |
| 标定数据不对 | 加载了旧版本或未加载 | 核对标定版本与路径 |
| 多传感器时间对不上 | 时间同步未完成就开机 | 先等同步，再进工作模式 |
| 远程连不上 | 网络/隧道未就绪 | 按 S8-03 四层排查 |
| 界面显示未就绪但设备可用 | 状态机初始化顺序问题 | 检查状态发布与界面订阅时序 |
| 每天都出同类报警 | SOP 缺验证点或未执行 | 补验证点，做成自检脚本 |
