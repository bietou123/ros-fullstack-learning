# S8-03 · 网络、VPN 与远程接入

> 验证状态：✅ 本机 Linux 实测了 `ss`、`ip route`、`getent hosts` 等排查命令；⚠ 未配置真实 VPN/隧道。示例地址使用文档保留网段，**不包含任何现场真实 IP 或凭据**。

## 1. 现场类比

现场打电话说「连不上」。你在办公室试，能连；他在现场试，不能连。最后发现：设备网线插错网口，路由不通。

远程排障最怕「猜」。**按层查：服务在不在听 → 本机路由通不通 → DNS 对不对 → 防火墙/隧道放不放行。**

## 2. 核心概念

### 2.1 四层排查

| 层 | 问题 | 命令 |
|---|---|---|
| 服务 | 端口有没有监听 | `ss -lntp` |
| 本机网络 | 地址、路由对不对 | `ip addr`、`ip route` |
| 名称解析 | 域名能不能解析 | `getent hosts`、`dig` |
| 通路 | 防火墙/隧道/对端 | `nc -vz`、`ping`、抓包 |

**先证明「服务在听」，再证明「路能通」，最后才怀疑 VPN。**

### 2.2 VPN 是什么、不是什么

- 是：在不可信网络上建立加密通道；
- 是：把远程设备纳入受控网络；
- **不是**：加速器；
- **不是**：安全的替代品（内部仍有权限与隔离问题）。

常见形态：

| 形态 | 说明 |
|---|---|
| 站点到站点 | 两个网络互通，适合固定现场 |
| 客户端 VPN | 单台设备接入，适合运维人员 |
| 零信任/跳板 | 先认证再授权，最小权限 |

### 2.3 远程接入原则

1. **不把设备管理端口直接暴露公网**；
2. 必须经过 VPN/跳板/网关；
3. 最小权限：只开需要的端口与账号；
4. 有审计：谁在什么时候连了什么；
5. 断线有安全行为：控制链路断开必须停机（S6-05），不能靠人喊。

### 2.4 延迟与稳定性

远程控制对延迟敏感：

| 指标 | 关注点 |
|---|---|
| RTT | 往返延迟，决定操作跟手程度 |
| 抖动 | 比平均延迟更影响体验 |
| 丢包 | 导致画面卡顿、指令丢失 |
| 带宽 | 决定视频质量 |

**用平均值评估远程链路是不够的，至少看 P95 和抖动。**

### 2.5 SSH 隧道（运维常用）

```bash
ssh -L 8080:127.0.0.1:80 ops@example.com
```

含义：本地 8080 → 经网关 → 目标机 127.0.0.1:80。适合临时排障，不适合长期生产（要有正式接入方案）。

## 3. 可复制命令 / 代码

```bash
# 本机监听了哪些 TCP 端口
ss -lnt

# 路由表：默认网关与网段
ip route

# 名称解析
getent hosts localhost

# 本机回环连通性
ping -c 1 127.0.0.1
```

预期：能看到监听端口、默认路由、`localhost` 解析结果，ping 回环成功。

## 4. 动手实验

**目标（35 分钟）**：为一台现场设备写一份远程接入方案，并按层验证。

1. 列出设备需要对外开放的服务与端口（越少越好）；
2. 画出接入路径：现场设备 → 现场网络 → 隧道/VPN → 运维端；
3. 说明认证方式与权限范围（只读？只特定端口？）；
4. 用 `ss` 确认监听端口与预期一致；
5. 用 `ip route` / `getent hosts` 验证本机网络与解析；
6. 断开链路，验证设备进入安全状态，而不是保持最后指令；
7. 写结论：断线后多久停机？谁能连入？如何审计？

**通过判据**：端口清单最小化、接入路径明确、断线安全行为经过验证。

## 5. 自动检查

```bash
ping -c 1 127.0.0.1 >/dev/null && getent hosts localhost >/dev/null && echo NET_OK
```

预期输出 `NET_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 能 ping 通但服务连不上 | 端口未监听/防火墙拦截 | `ss -lnt`，查防火墙 |
| 局域网能连、远程不能 | 未接 VPN/隧道或路由缺失 | 查接入路径与路由 |
| 域名解析失败 | DNS 配置错误 | `getent hosts`、换 DNS 测试 |
| 远程画面卡顿 | 带宽不足/丢包/抖动 | 看 P95 RTT 与丢包率 |
| 断线后设备继续动 | 控制链路无超时保护 | 加看门狗，验证断线停机 |
| 多人同时连入互相干扰 | 无权限隔离/会话管理 | 分账号、最小权限、单会话 |
| 管理端口暴露公网 | 图方便直连 | 立即收敛到 VPN/跳板 |
