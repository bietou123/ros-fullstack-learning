# S10-06 · 验收报告与答辩

> 验证状态：✅ 本机 Linux 实测了报告完整度评分；⚠ 报告模板为通用工程实践，具体格式以交付要求为准。

## 1. 现场类比

报告写了三十页，核心结论是「系统运行稳定、效果良好」。评审只问了一句：「哪条数据支持这个结论？」

报告不是散文，是**证据索引**。每个结论后面都要能指到一条数据、一段日志或一个可复现的命令。

## 2. 核心概念

### 2.1 报告结构

| 章节 | 内容 |
|---|---|
| 摘要 | 项目目标、完成情况、关键结论 |
| 范围 | 做了什么，明确不做什么 |
| 架构 | 模块、数据流、部署形态 |
| 功能验收 | 检查点、判据、结果、证据 |
| 安全验收 | 急停、看门狗、故障态、复位 |
| 性能与限制 | 测得的指标、模型边界、未验证项 |
| 故障演练 | 故障类型、动作、恢复时间 |
| 数据与证据 | 证据编号与位置 |
| 改进项 | 已知问题、后续计划 |
| 附录 | 版本表、配置说明、复现步骤 |

### 2.2 结论必须配证据

| 结论 | 需要的证据 |
|---|---|
| 状态机拒绝非法转换 | 测试输出 + 转换日志 |
| 执行器响应达标 | 阶跃曲线 + t90 数值 |
| 故障后自动恢复 | 演练记录 + 时间戳 |
| 部署可回滚 | 回滚耗时记录 |

**没有证据的「通过」，评审只能当成意见，不能当成结论。**

### 2.3 验收结果表

```
检查点 | 判据 | 结果 | 证据编号 | 备注
```

关键项失败必须写清楚，不能藏在附录里。

### 2.4 主动写限制

- 哪些步骤未实测（例如真实硬件启动）；
- 模型简化了什么（S10-02）；
- 样本量多少、是否覆盖边界；
- 哪些结论只在本环境成立。

**主动写限制不会降低评价，隐瞒才会。**

### 2.5 答辩的三分钟结构

1. 问题是什么（30 s）；
2. 方案是什么（60 s）；
3. 证据是什么（60 s）；
4. 限制与下一步（30 s）。

**先给结论，再给过程。** 评审不关心你调了多少次参数。

### 2.6 预判问题

提前准备：

- 为什么这样建模？误差多大？
- 断网/断电会怎样？
- 怎么证明不是偶然通过？
- 如果数据量翻十倍呢？
- 哪些是抄的、哪些是你做的？

答不上来的问题，如实说「未验证」，并给出验证方法。

### 2.7 可复现

- 一条命令启动；
- 版本号齐全；
- 数据来源明确；
- 别人照文档能跑出同样结果。

**不可复现的成果，在评审眼里等于不存在。**

### 2.8 脱敏

报告中不得出现真实 IP、序列号、账号、客户名称、内部链接。版本表用占位符或内部编号。

## 3. 可复制命令 / 代码

```bash
# 报告完整度：按章节权重计分
python3 -c "report=[('摘要',True,0.05),('系统架构',True,0.15),('功能验收',True,0.25),('安全验收',True,0.25),('故障演练',True,0.15),('数据与证据',False,0.10),('改进项',True,0.05)]; score=sum(w for _,ok,w in report if ok); print('sections=%d score=%.2f missing=%s'%(len(report),score,[n for n,ok,_ in report if not ok]))"
```

预期：

```
sections=7 score=0.90 missing=['数据与证据']
```

含义：缺「数据与证据」一章，权重 0.10，当前得分 0.90——**结论再多，缺证据也不算完整。**

## 4. 动手实验

**目标（45 分钟）**：完成毕业项目报告与答辩准备。

1. 按 2.1 写出章节骨架；
2. 每个结论填一条证据（编号 + 位置）；
3. 用第 3 节代码计算完整度，补齐缺失章节；
4. 写「限制与未验证项」至少 3 条；
5. 准备 10 个预判问题与回答；
6. 让另一个人按文档复现一次；
7. 做一次 3 分钟模拟答辩并计时。

**通过判据**：每个结论有证据；限制写清楚；他人可复现；三分钟能讲完。

## 5. 自动检查

```bash
python3 -c "report=[('摘要',True,0.05),('系统架构',True,0.15),('功能验收',True,0.25),('安全验收',True,0.25),('故障演练',True,0.15),('数据与证据',False,0.10),('改进项',True,0.05)]; score=sum(w for _,ok,w in report if ok); miss=[n for n,ok,_ in report if not ok]; assert abs(score-0.90)<1e-9 and miss==['数据与证据']; print('REPORT_OK')"
```

预期输出 `REPORT_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 评审不信结论 | 无数据/日志证据 | 每个结论编号对应证据 |
| 报告被问倒 | 未写限制与边界 | 主动列未验证项 |
| 别人复现不了 | 版本/步骤缺失 | 补版本表与一键启动 |
| 答辩超时 | 过程讲太多 | 结论先行，3 分钟结构 |
| 关键失败被忽略 | 结果表未分级 | 关键项单独标红 |
| 报告泄露敏感信息 | 直接贴现场材料 | 脱敏后再入报告 |
| 数据对不上 | 多次实验混用 | 固定数据集与版本 |
