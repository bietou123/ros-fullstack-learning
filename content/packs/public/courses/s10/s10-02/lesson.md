# S10-02 · 虚拟 CAN + 执行器模型

> 验证状态：✅ 本机 Linux 实测了一阶执行器模型、饱和与 t90 计算；⚠ 未使用 vcan/socketcan 实机总线，也未拟合真实设备参数；模型参数为**教学示例值**，不代表任何实际机型。

## 1. 现场类比

每改一次控制逻辑就上一次真机：慢、危险、不可重复，出了问题还伤设备。

如果先把执行器做成一个可运行的模型，控制代码就能在桌面上反复跑——**逻辑问题在桌面上解决，真机只用来验证模型没覆盖的部分。**

## 2. 核心概念

### 2.1 虚拟 CAN 是什么

CAN 是差分总线，帧由「ID + 数据长度 + 数据」组成。虚拟 CAN 用软件模拟收发：

| 方式 | 说明 |
|---|---|
| vcan / SocketCAN | Linux 内核虚拟总线，应用程序无感知 |
| 进程内队列 | 最简单的模拟，适合单进程实验 |
| 回环 / 桩程序 | 用脚本扮演对端设备 |

**目的不是替代真实总线测试，而是让逻辑可以先跑起来。**

### 2.2 帧设计的基本原则

| 项 | 要点 |
|---|---|
| 帧分类 | 命令 / 状态 / 心跳分开，ID 不重叠 |
| 周期 | 命令与状态各自有明确周期 |
| 字节序 | 统一端序，写进文档 |
| 缩放 | 物理量 → 原始值，比例因子与偏移明确 |
| 校验 | 至少校验长度与范围；关键帧加序列号 |
| 超时 | 心跳缺失即判定链路异常（S6-05） |

具体 ID、字节布局属于项目内部协议，**公开内容不写真实协议定义**。

### 2.3 执行器的一阶模型

```
v[k+1] = v[k] + (u[k] − v[k]) · dt / τ
```

- `u`：限幅后的目标速度；
- `v`：当前速度；
- `τ`：时间常数，反映响应快慢；
- 阶跃响应的 90% 时间约为 `2.3τ`。

### 2.4 现实中的三个非理想项

| 特性 | 建模方式 |
|---|---|
| 饱和 | `u = clamp(cmd, −vmax, +vmax)` |
| 死区 | 小指令直接置零，避免抖动 |
| 速率限制 | 每秒最大变化量，`rate·dt` |

**先限幅、再限速、再进动态模型**——顺序错了，模型会给出物理上不可能的结果。

### 2.5 参数从哪里来

- 从真实设备的阶跃响应拟合 `τ`；
- 量程、死区查设备手册或实测；
- 所有参数标注来源与适用范围。

**模型参数不是拍脑袋的默认值。** 本课使用 `τ=0.12 s` 仅为演示。

### 2.6 虚拟模型的边界

模型适合验证：状态机逻辑、指令范围、超时行为、链路时序。

模型**不适合**验证：液压非线性、温度漂移、机械磨损、精度指标。

**别拿模型结果去签精度验收。**

### 2.7 测试用例

1. 阶跃：`u=1.0`，测 t90 与稳态值；
2. 超限：`u=1.5`，确认被饱和到 `vmax`；
3. 零指令：确认速度收敛到 0；
4. 方向反转：确认没有跳变；
5. 长时间运行：确认数值不发散。

## 3. 可复制命令 / 代码

```bash
# 一阶执行器：饱和 + 阶跃响应 t90
python3 -c "tau=0.12; dt=0.01; vmax=1.0; cmd=1.5; vs=[0.0]; [vs.append(vs[-1]+(min(cmd,vmax)-vs[-1])*dt/tau) for _ in range(100)]; t90=next(i*dt for i,v in enumerate(vs) if v>=0.9); print('v_final=%.3f t90=%.2fs'%(vs[-1],t90))"
```

预期：

```
v_final=1.000 t90=0.27s
```

含义：指令 1.5 被饱和到 1.0；约 0.27 s 达到 90%，与 `2.3 × 0.12 ≈ 0.28 s` 吻合。

## 4. 动手实验

**目标（45 分钟）**：实现一个可测试的虚拟执行器。

1. 定义命令帧与状态帧的字段（ID、周期、缩放、超时）；
2. 实现一阶模型 + 饱和 + 死区 + 速率限制；
3. 跑阶跃测试，记录 t90 与稳态值；
4. 把 `τ` 改成 0.06 / 0.24，观察 t90 变化是否符合 `2.3τ`；
5. 输入超限指令，确认饱和生效；
6. 写结论：模型与真实执行器最可能差在哪？哪些结论不能从模型得出？

**通过判据**：阶跃测试通过；饱和与死区可验证；明确写出模型的适用边界。

## 5. 自动检查

```bash
python3 -c "tau=0.12; dt=0.01; vmax=1.0; cmd=1.5; vs=[0.0]; [vs.append(vs[-1]+(min(cmd,vmax)-vs[-1])*dt/tau) for _ in range(100)]; t90=next(i*dt for i,v in enumerate(vs) if v>=0.9); assert abs(t90-0.27)<1e-9 and vs[-1]>0.99; print('ACTUATOR_OK')"
```

预期输出 `ACTUATOR_OK`。

## 6. 常见故障

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 模型响应与实机差很多 | τ 未按实测拟合 | 做实机阶跃，重新拟合 |
| 指令超限后模型速度异常 | 未做饱和 | 先 clamp 再进模型 |
| 小指令导致抖动 | 无死区 | 加死区并回差处理 |
| 速度跳变 | 未做速率限制 | 加 `rate·dt` 限制 |
| 长时间仿真数值发散 | 步长过大 | 减小 dt，检查稳定性 |
| 虚拟总线收不到帧 | 周期/ID/端序不一致 | 抓帧核对定义 |
| 用模型结果签精度 | 模型边界不清 | 精度必须实机验证 |
