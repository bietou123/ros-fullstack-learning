## 本次修复的关键缺陷

**内容包哈希算法漂移**：`scripts/build-pack.mjs` 用原始 `manifest.json` 的 `min_app_version` 参与哈希，而 `packages/core` 用打包后 manifest 的 `minAppVersion`，导致核心库对合法内容包计算出的哈希永远不同。影响：设置页导入私有包时误报「哈希校验未通过」，且验收第 1/6/10 条存在假阳性风险。

修复：三处（构建脚本、`verify.mjs`、`@rl/core`）统一使用固定字段表
`id/name/version/visibility/minAppVersion/license/description`；新增单测「构建脚本产出的内容包必须通过核心库校验」，防止再次漂移。重新构建后四端哈希一致。

**全新检出直接 `verify` 失败**：`apps/web/public/content/pack.json` 已被 `.gitignore` 排除，干净克隆没有该文件，`pnpm verify` 在内容包检查处直接失败。虽然 README 快速开始要求先 `pnpm build`，但 `verify` 单独执行时不应踩空。

修复：`scripts/verify.mjs` 检测到 `pack.json` 缺失时自动执行 `scripts/build-pack.mjs`；README 命令表已注明首次运行会自动生成内容包。

**Android 学习数据导出静默失效**：Android WebView 113 不支持 `navigator.share`，也没有 `DownloadListener`，桌面端使用的 blob `<a download>` 在 APK 内点击后无任何反馈，验收第 8 条实际不可用。这个问题直到在无窗口模拟器上做导出链路验证才暴露，说明「打包成功 + 哈希一致」不能替代运行验收。

修复：原生平台改用 `@capacitor/filesystem` 写入缓存目录，再通过 `@capacitor/share` 调起系统分享面板；Web 端保留下载逻辑。模拟器已验证导出文件（820 B）并完成 SAF 导入闭环。该修复已进入 v0.1.1 补发（见下节），v0.1.0 资产保持原样不替换。

**私有内容包导入必然失败**：`savePrivatePack` 把内容包对象直接写入 keyPath 为 `id` 的 IndexedDB 存储，但内容包顶层没有 `id`（真实 id 在 `manifest.id`），浏览器抛 `DataError`。这并不是 Android 特有问题，Windows/Linux/Android 三端的私有包导入都会失败；v0.1.0 / v0.1.1 都受影响。此前验收只核对了哈希算法与导入界面，没有跑通导入链路。

修复：`packages/core/src/store.ts` 新增 `privatePackRecord()`，从 `manifest.id` 生成存储键；新增单测覆盖。Android 模拟器已实测 JSON/ZIP 导入、双向切换、重启持久化、只读浏览与删除回退。该修复进入 v0.1.2 补发。

## M1 交付补齐：错题本（2026-11-03）

M1 任务书要求「测验、错题本、间隔重复」，此前只实现了待复习列表与 SM-2 调度；测验结果虽保存 `answers`，但没有错题界面。

- `latestQuizResults()` 抽出「每课最新一次测验」逻辑，`dueReviews` 复用；新增单测，核心库测试 13/13。
- 进度页新增「错题本」：按每课最新一次测验逐题列出答错题目、你的答案、正确答案与解析，并链接回课程；重做后自动更新，答对即移出；无错题时显示空状态。
- 桌面隐藏冒烟新增 `wrongBookOk`：S0-01 三题全选第一项（正确答案均为第二项）后错题本出现 3 条，断网模式同样通过。
- Android 34 x86_64 模拟器（源码 debug APK，清空应用数据后）：首次全错提交 → 3 条解析、错题本 3 条；重做全对 → 3 条正确解析、错题本清空。
- 该功能在 v0.1.2 发布之后合入 `main`，**未包含在已发布的 v0.1.2 产物中**；后续发版时随包生效。
